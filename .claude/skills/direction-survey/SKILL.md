对论文库内的**方向 / 学科**出具综述与论断，**两种模式**：

**① 方向级（缺省，v2 起不变）**：对一个**细分研究方向**出**以演进为主线的综述**。**最终交付物 = 读者不看任何单篇论文，也能看懂这个方向：起源 → 骨干定型 → 分岔成几大技术家族 → 各家族沿革/卡点 → 生态里能比什么/不能比什么 → 前沿与缺口 → 下一步往哪走。** 论文（库内已分析 + 库外锚点）一律只作为附着在**阶段 / 技术家族**上的证据与里程碑；逐篇的骨架/损失/指标/短板不再正文展开，只进「论文定位索引」附录一行。

**② 学科级（v3.0 新增）**：对一个**学科**（如 语音与音频信号处理）出**细分方向论断**。**最终交付物 = 读者不看任何单篇论文，也能看懂这个学科现在其实是几块、每块成熟/活跃/空白到什么程度、哪块本不该单列、有没有该切而没切的一刀。** 每块给四要素判断（成立度 / 成熟度 / 活跃度 / 空白度）+ 边界一句话，并受**样本不足纪律**约束（证据薄的判断必须标「样本不足·推断」或填 `不详`，不许硬判）。

> **方向级 I/O**：输入 `论文库/<学科>/<方向>`；输出 `<方向>/方向综述/方向综述-<YYYY-MM-DD>.md(+.docx)` + G1–G4 四张图（G1/G2 出 Mermaid，G3/G4 语义图不出）+ 可复跑 `工作/方向档案.json`。
> **学科级 I/O**：输入 `论文库/<学科>`；输出 `<学科>/方向论断/学科方向论断-<YYYY-MM-DD>.md(+.docx)` + T1 学科地形图（PNG，不出 Mermaid）+ 可复跑 `工作/学科档案.json`。

> **依赖**：五类图 **全用本 skill 自带 `scripts/ds_fig.py`**（fig 类型 `stage/family/quad/audit/terrain`）；pa_fig 只用于默认 lineage/scatter（本 skill 不用）；docx 用 pandoc（可选）。配色/无 emoji/CJK 纪律沿 pa_fig，详见 `references/reuse-notes.md` 与 `references/figure-design.md`。

## 触发与 I/O
- **方向级触发**：用户说「出方向综述 / 写研究方向报告 / 分析 <方向> 怎么发展 / 发展脉络 / 前沿瓶颈 / 能开什么新方向」。
- **学科级触发**：用户说「这个学科分成哪几个方向 / 细分方向论断 / 学科地形 / 这个学科哪块成熟哪块空白 / 学科的刀该怎么切 / 给我一份学科方向论断」。
- 拿不准（只说「看看 <学科> 的情况」）→ 看粒度：问的是**一个方向内部**怎么演化 = 方向级；问的是**学科由哪几块组成** = 学科级；两边都要时**先学科级定块、再按块补方向级**。
- 方向级输出（全部落 `<方向>/方向综述/`）：
  - `方向综述-<YYYY-MM-DD>.md` / `.docx`
  - `assets/{G1发展时间线, G2方法脉络关系图, G3前沿成熟度机会, G4生态盘点矩阵}.png`（G1=阶段演进带、G2=家族泳道、G3=机会象限、G4=生态盘点矩阵；G1/G2 另出 `.mermaid`）
  - `工作/方向档案.json` + `工作/fig_G1..G4*.json`（中间档，供复跑增补）
- 学科级输出（全部落 `<学科>/方向论断/`）：
  - `学科方向论断-<YYYY-MM-DD>.md` / `.docx`
  - `assets/T1学科地形图.png`（行=细分方向、列=成立度/成熟度/活跃度/空白度/库内样本/边界一句话；不出 Mermaid）
  - `工作/学科档案.json` + `工作/fig_T1学科地形图.json`（中间档，供复跑增补）
- 登记：在 `论文库/README.md` 对应小节更新链接（方向级 → 方向综述行；学科级 → 该学科节新增「方向论断」行）；旧版按根 README「版本留档约定」快照入 `存档/论文层快照/`。

## 范围与口径（开工前先钉死）
- **叙事对象是方向不是论文**：库内该方向全部已分析论文 + 各报告 §5 库外锚点，都是证据；正文围绕「阶段 + 技术家族」组织。**单一论文的横评/档案不进正文**（除附录索引一行）。
- **学科级同理**：叙事对象是**细分方向**，不是论文，也不是单个方向内部的技术家族（家族归方向级 G2）。
- **节点**（图中）：库内已分析 = 实心金色 `this`；库外锚点 = 角色浅色 + 虚线框（`pre/rival/module/next/adj`），标「未读」。
- **边**：只用报告已有表述拼。**图内边标签只写「关系动词 + 极短出处」**（如 `模块来源·§5 R3`），完整证据放：stage 图 → 阶段脚注；family 图 → 图下「边注表」；查不到 → 如实进缺口，不猜。
- **口径容错**：v2/v3 报告混存归一规则见 `references/relation-vocab.md`；库外锚点缺年份 → `年份?`，不瞎填。
- 未分析 PDF 只进「机会/待读候选」（学科级还可在**过门**后作新刀的待读证据），不给假档案。
- 同源去重：学位论文第 3 章 = 同组期刊预印本 → 两个库内节点 + 边标「同源衍生」，不合并。

## 工作流（TaskCreate 建 8 个任务跟踪，逐步 TaskUpdate）
```
- [ ] 步骤 0: 选方向 + 扫描（ds_scan.py；多候选 AskUserQuestion）
- [ ] 步骤 1: 通读建档（读全部已分析报告 → 只收【阶段事实/家族事实/锚点】三类证据 → 方向档案.json）
- [ ] 步骤 2: G1 阶段演进图（定 3–5 阶段 → fig:"stage" JSON → ds_render 渲染 PNG/Mermaid）
- [ ] 步骤 3: G2 技术家族泳道图（切 2–5 家族 → fig:"family" JSON → 渲染；跨族关系只画相邻泳道虚线进 cross，非相邻进 cross_notes 文字边）
- [ ] 步骤 4: 论文定位索引（附录 A 一行/篇）+ G3 机会象限（quad）+ 图读法/正文数值核对
- [ ] 步骤 4.5: 生态盘点矩阵（fig:"audit" G4：谱系带 × 评测协议 × 复杂度口径，能比什么/不能比什么）
- [ ] 步骤 5: 前沿关注点 / 发展瓶颈 / 机会与新方向（判据见 opportunity-method.md，配 G3 quad）
- [ ] 步骤 6: 装配 报告 md(模板，含每图「图读法」) + docx + 落位 + 登记 论文库/README
- [ ] 步骤 7: 收尾自检（完成线 gate）+ 向用户汇报
```

### 步骤 0：选方向并扫描
同 v1：用户给了 `<学科>/<方向>` 就用；没给 → `ds_scan.py "<方向目录>"` 前先 AskUserQuestion 单选候选；跑完核对报告名与论文夹对应、是否有同源对。

### 步骤 1：通读建档（只收三类证据，别抄逐篇）
对每篇已分析论文读报告，产出**三类方向级证据**（不是逐篇 digest 复述）：
1. **阶段事实**：它把哪个子问题推进/定义了、属于哪一代（年份佐证）；
2. **家族事实**：它属于哪条技术谱系（骨干/表示域/实时策略）、与同家族/异家族的前后关系（报告 §5 R1–R4、演进树）；
3. **锚点**：§5 收录的库外论文 → 标题+角色+出处，去重合并（库内已有同题 → 提升为库内节点）。
> 锚点元数据读不到 → 标「未核/年份?」；§5 的 R5（邻域/评测锚）和数字细节一律只当背景，不进正文主线。产出更新 `方向档案.json`。

### 步骤 2：G1 阶段演进图（方向怎么走过来的）
- 把方向演进切 **3–5 个阶段**，每阶段钉四件事：**name**（一句话定性：起源/骨干定型/主流成型/分岔/前沿）、**period**、**driver**（这段为何发生：外部需求/骨干被谁引入/评测挑战）、**代表 work(s)**（库内 `this` 实色 / 库外锚点浅虚线）、**breakthrough + gap**（阶段级标志与遗留，各 ≤1 行，阶段级归并，不逐篇）。
- 组装 `fig:"stage"` JSON（schema 见 `references/figure-design.md`）→ `ds_render.py` 出 PNG/Mermaid。
- **图上文字纪律**：works 标签 ≤2 行短名（如 `Personalized PercepNet 2021`）；breakthrough/gap 用阶段级结论，不带单篇指标细节。
- 正文配**图读法**（结构见模板）与逐阶段 1–2 段"驱动故事"。

### 步骤 3：G2 技术家族泳道图（现在岔成几股）
- 先归纳 **2–5 条技术家族**（谱系主线；每条 = 同一骨干/表示域/路线）。每个库内节点与库外锚点挂到所属家族（同源衍生对同属一族）。
- 组装 `fig:"family"` JSON：
  - 每条 **lane**：`name`（家族名+一句约束/擅长）+ `nodes`（道内从左到右按血缘/时间排）+ `edges`（道内继承边，短标签）。
  - **cross**（跨家族关系：模块来源/竞品/邻域）：给 `from/to/label/note/evidence` → 渲染为带编号虚线，编号解释 = **图下边注表**。**红线：虚线只画上下相邻泳道**（出/入点取两框相对一侧的框边、走框外不压字）；非相邻泳道之间的关系**不画线**，挪进 `cross_notes`（label/note/evidence）→ 边注表末尾记〔文字·未画线〕。
- 出 PNG/Mermaid 后，正文放：G2 图 + **图读法**（几大道、主干在哪）+ 每家族一小节（谱系链文字 + 代表里程碑 + 卡点）+ **跨家族交叉**小段 + 附录引用 G2 边注表。
- 排不下：图保持家族主干，竞品/邻域锚点只放「与主线最近的一跳」，远的进边注表文字，别硬塞节点。

### 步骤 4：论文定位索引 + G3 机会象限 + 图读法/正文数值核对
- 不再做横评大表与逐篇档案。产出 **附录 A 论文定位索引**，每篇一行：
  `短名 (年, 库内/锚点) ｜ 家族·阶段 ｜ 贡献一句话(方向口径) ｜ 现状/短板一句(出处) ｜ 关键指标(1–2 个, 带口径)`。
- **G3 机会象限**：从 §5 机会 O1–O6 归纳，组装 `fig:"quad"` JSON——x=机会空间/空白度（右=越没人系统做，判据写进 sub 消除歧义）、y=前沿活跃度，O 点坐标 0–1 仅示意，右上=又热又空=最该投（读法见 figure-design.md）。
- 核对：正文与图上引到的每个数值、每个阶段/家族结论，都溯源到报告某节；冲突/口径不通约 → 进缺口。

### 步骤 4.5：生态盘点矩阵（G4，fig:"audit"）
- 回答「这个方向生态里谁做了、各用什么协议自证、算力口径怎么各说各话」：行=方法（粗黑带=研发谱系，金实=库内）、列分三组（方法 / 评测协议：带宽·主指标·评测构型 / 复杂度口径：参数·算力·因果延迟）。
- 诚实纪律：协议互斥（如 48k/16k/8k 三种刻度）与单位互斥（%CPU / RTF / MACs）**如实画在格子里并写进图注**，明确只有带内同协议行才可排序；无数值的下游锚点（只给目标）不入表、作文字。
- JSON：`cols[]`（label/key/w）+ `col_groups[]`（跨列组名）+ `bands[]`（name + rows[]：type/cells{key:text}）+ note（读法）。渲染见 figure-design.md。

### 步骤 5：前沿 · 瓶颈 · 机会（方向级判读）
按 `references/opportunity-method.md`（G3 空白度判据）出机会，每条判断给 2–4 前沿子题 / 瓶颈三桶 / 3–6 机会，**以家族/方向为单位写**，不逐篇复述报告批判；机会落点进 G3 quad。

### 步骤 6：装配报告
1. 复制 `templates/方向综述-模板.md` → `方向综述/方向综述-<日期>.md` 填全部章节。
2. 每张图嵌 PNG 后**紧跟该图的「图读法」块**（家族图还带边注表）——图与解释必须同屏，不许图放 §2 解释在 §4。
3. 渲染：G1–G4 JSON 用 `ds_render.py` 出 PNG（G3/G4 不出 Mermaid）；G1/G2 另出 Mermaid；**每条出图命令加 `--qa`**（内置几何自检：文字出界/压叠 → 退出码非 0，先修数据再继续）。
4. docx：pandoc 从 md 转（cd 到 `方向综述/` 保证图路径）。
5. 落位 + 更新 `论文库/README.md` 该方向「方向综述」行；旧版先快照。

## 学科级工作流（v3.0；TaskCreate 建 8 个任务跟踪）

> 判法与纪律**唯一来源** = `references/discipline-method.md`（切分判据 / 四要素口径 / 边界写法 / 样本不足纪律 / 新开一刀证据门）。图纪律见 `figure-design.md` 的 T1 节；schema 见 `reuse-notes.md`。

```
- [ ] 步骤 D0: 选学科 + 扫描（ds_scan.py --discipline → 学科档案.json；学科含多方向时逐方向清点）
- [ ] 步骤 D1: 切块 —— 按切分判据四条把学科切成候选细分方向（含"现在没建目录但该有一块"的候选）
- [ ] 步骤 D2: 逐块取证 —— 读各方向已分析报告 §1/§2/§4/§5 + 方向综述(若有) → 逐块四要素判据 + 边界一句话
- [ ] 步骤 D3: 新开一刀判定（过门见 discipline-method §六；未过门只进正文机会）
- [ ] 步骤 D4: 组装 T1 terrain JSON → ds_render --qa 渲染（样本不足的行必须标红字标注）
- [ ] 步骤 D5: 写论断报告（模板 学科方向论断-模板.md：地形图 + 逐块 §3 + 新刀 §4 + 学科级结论 §5）
- [ ] 步骤 D6: 装配 docx（pandoc，cd 到 方向论断/）+ 落位 + 登记 论文库/README
- [ ] 步骤 D7: 收尾自检（学科级完成线 gate）+ 向用户汇报
```

### D0 扫描学科
`python .claude/skills/direction-survey/scripts/ds_scan.py "论文库/<学科>" --discipline` → `方向论断/工作/学科档案.json`（逐方向：篇目 / 报告引擎与结构变体 / 各报告 §5 `anchor_marks` 命中 / 是否有方向综述件 / 未读 PDF / 样本充足性提示）。
- `notes` 里的样本不足与「铺开方向 <3」提示**照单执行**，不是建议。
- 学科下没有子目录或只 1 个 → 直接告诉用户「本学科尚未成地形」，别硬造块。

### D1 切块
- 每块必须过 `discipline-method.md` §二 四条（独立任务定义 / 骨干或评测独立 / 有连续谱系 / 库内可落地）。
- **不许把约束当块**：实时、轻量、低资源、因果、某数据集、某指标 → 进块内 `why` 或地形图 `note`。
- 结果分两类：**库内已建目录**（有方向目录/已分析报告）与**论断新增候选**（本库没建目录，但可能该有一块）。
- 切完先自查：块之间边界互斥吗？某两块重合 >50% → 合并或改切法。

### D2 逐块取证（每块四要素 + 边界）
- 证据只取：库内已分析报告 §1/§2/§4/§5；各报告 §5 收录的库外锚点（标「锚点≠已读」）。**库外新检索与未分析 PDF 不作证据**。
- 逐块写：任务定义一句话 / 成立度（四条命中情况）/ 成熟度 / 活跃度 / 空白度（四条空白度判据逐条）/ 边界一句话 / 库内样本（不足门槛 → 「样本不足·推断」）/ **反例反证据**（没有写「未发现」）/ 缺口。
- 与已有 `方向综述` 口径对齐；不一致 → 以报告证据为准并把冲突记进 §6 缺口。

### D3 新开一刀判定
- 过门四条（D1 的切分判据 1–3 + 锚点聚集≥2 篇报告 或 贴切的未分析 PDF）；**未过门 → 只进报告 §4「候选方向（证据不足）」，不进 T1**。
- 每把过门的刀写：刀口 / 与邻块边界 / 现有证据（几条锚点、哪个 PDF、出处）/ 还缺什么才能建目录。

### D4 组装 T1 地形图
- 组装 `fig:"terrain"` JSON（见 `figure-design.md` T1 节）：`cols` 固定七列（细分方向 / 成立度 / 成熟度 / 活跃度 / 空白度 / 库内样本 / 边界一句话），`bands` = `库内已建目录` + `论断新增候选`，行**带内按成熟度降序**。
- 三维各给 `hue`（成熟度蓝 / 活跃度红 / 空白度绿）；每格 `why` **一行**；证据不足填 `不详`；样本不足的行用红字 `{"text":…,"color":"#c0392b","bold":true}`。
- `conclusion` 必填（学科级一句话论断；方向数 <3 → 写「本库目前只铺开这几块」+「样本不足·推断」）。
- 渲染：`ds_render.py "工作/fig_T1学科地形图.json" --png "assets/T1学科地形图.png" --mermaid - --qa`（**必须带 `--qa`**；退出码非 0 先修数据）。

### D5 写论断报告
复制 `templates/学科方向论断-模板.md` → `方向论断/学科方向论断-<日期>.md`，填全：速览卡 / §1 口径与证据门 / §2 T1 图 + 图读法 + 逐块速览表 / §3 逐块论断（含反例与缺口）/ §4 新开一刀 + 待读候选 / §5 学科级结论与三条建议 / §6 缺口账本 / 附录 A 方向与报告索引。

### D6 装配 docx + 落位 + 登记
`cd "<学科>/方向论断"` → pandoc（TOC，depth 2）→ 更新 `论文库/README.md`（该学科节新增「方向论断」行；原「方向综述」行不动）；重跑覆盖旧版前先快照入 `存档/论文层快照/`。

### D7 收尾自检（学科级完成线 gate）
- [ ] 每块都过切分判据四条；**没有把约束（实时/轻量/低资源/某数据集）当块**；
- [ ] 每块四要素齐、每格 `why` ≤1 行；证据不足的格填 `不详`（**没有猜档**）；
- [ ] 每块有边界一句话，且与邻块边界互斥性说得清；
- [ ] 样本不足纪律执行到位：方向 <2 篇的行标「样本不足·推断」；**独立研究线 <2 条（篇数够但为同源衍生对）同样标**；学科 <3 块时学科级结论写成「本库目前只铺开这几块」；
- [ ] **库外新检索/未分析 PDF 没被当作论断证据**（只出现在 §4 待读候选）；
- [ ] 新刀都写了过门判定；未过门的刀不出现在 T1 图上；

- [ ] 渲染命令带 `--qa` 且几何自检通过（退出码 0）；图无 emoji、无缺字形；

## 质量纪律
1. **叙事对象 = 方向，证据 = 论文报告**：别让单篇的指标/短板反客为主；指标只在「证明家族/阶段论点」时才出现。
2. **图是第一主角**：宁可少放节点、少写长边标签，也要关系可读；看不懂的图不如不放。
3. **证据驱动**：阶段/家族/前沿/瓶颈每条判断指向具体报告章节；找不到就写「缺口/推测」。
4. **数值口径**：正文指标带论文名+口径；两版冲突显式标注。
5. **图红线**：无 emoji 入图；CJK 无豆腐块（含 U+2194 ↔ 之类易缺字形）；边标签短；跨族关系用编号不写长句；**箭头/虚线一律走框外不压字**；文字不越画布、两两不压叠（渲染命令加 `--qa` 做内置几何自检）——T1 亦然。
6. **受限数据/文件红线**：不代下受限数据、不把未读库外论文当已读、只登记官方入口。
7. **存档**：旧方向综述/旧学科论断、被覆盖的 `方向档案.json`/`学科档案.json` 快照入 `存档/`，不自动删。
8. **学科级纪律（v3.0）**：一切论断**带成立度与证据量**；样本不足必须标「样本不足·推断」或填 `不详`（**自信不等于有据**）；不把约束（实时/轻量/低资源/某数据集）当细分方向；**库外新检索与未分析 PDF 不进论断打分**（只入待读候选）；图上判断不许比正文更硬。判法与完整纪律见 `references/discipline-method.md`。
