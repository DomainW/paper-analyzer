# 方向级 / 学科级图的设计与解释纪律（figure-design）

> direction-survey v3.0 的核心参考（纪律**单一来源**：图怎么设计/别踩什么坑都以本文件为准；SKILL.md 步骤与 reuse-notes 的 schema 只作引导，不重复展开——改图纪律先改这里）。v1 的三张图「关系不清」的根因大多不在渲染器，而在**作者把图上塞了太多东西**：长证据写进边标签、把"阶段"和"论文"画成同一类框、把所有锚点平铺成一张网。
> v2 起只保留方向级图型（均由本 skill 自带 `scripts/ds_fig.py` 渲染），四张图分工固定，每一步都规定「放多少、标签多短、解释怎么配」；v3.0 增设**学科级**图型 **T1 学科地形图**（`fig:"terrain"`），与方向级四图并列但不混用。

## 四张图的分工与原则

| 图 | 文件 | 型 | 回答 | 画布概念 | 模式 |
|---|---|---|---|---|---|
| G1 | G1发展时间线 | `fig:"stage"` | 方向**怎么走过来的**（时间/阶段） | 一列一个阶段带 | 方向级 |
| G2 | G2方法脉络关系图 | `fig:"family"` | 现在**岔成几股、谁借谁**（结构/血缘） | 一条道一个技术家族 | 方向级 |
| G3 | G3前沿成熟度机会 | `fig:"quad"` | 哪个机会**又热又空**（最该投） | 0–1 象限：x=机会空间/空白度，y=前沿活跃度 | 方向级 |
| G4 | G4生态盘点矩阵 | `fig:"audit"` | 生态里**谁做了、能比什么不能比什么** | 行=方法（粗黑带=谱系），列=评测协议×复杂度口径 | 方向级 |
| T1 | T1学科地形图 | `fig:"terrain"` | 学科**其实是几块、哪块成熟哪块空、哪块该重切** | 行=细分方向（分带），列=成立度/成熟度/活跃度/空白度/样本/边界 | **学科级** |

G1/G2 是节点-边图（出 PNG + Mermaid 留档）；G3/G4/T1 是**语义图**（象限/矩阵/分级表，只出 PNG，不出 Mermaid）。pa_fig 不再参与这些图（只留给默认 lineage/scatter 类老图）。**方向级与学科级不混用**：一个 `<方向>` 目录出 G1–G4，一个 `<学科>` 目录出 T1。

原则（无论哪张）：
1. **图的第一读者是不懂单篇论文的人**。一个节点能让读者"不点开论文也大概知道是什么"，标签才算合格。
2. **宁可少，不可乱**。放不下就归并进文字/边注表，不要在图上堆出 25+ 节点或跨 5 层的长边。
3. **颜色说身份、线型说关系、编号省长话**。图上不出现长证据句——证据进正文/边注表/附录索引。
4. **每张图必须自带「图读法」**，紧跟在图后面（不同页等于没有）。
5. **几何红线**：箭头/虚线一律走**框外**、不穿框不压字；文字不出画布、两两不压叠（见「几何红线」）。

## G1 fig:"stage" 阶段带图 —— JSON 与设计纪律

阶段带图是"阶段故事的配图"：一列一个阶段带，带顶=阶段名+时期+推动力，带中=代表工作，带底=突破/遗留，带间一根转向箭头。

```json
{
  "fig": "stage",
  "title": "TSE 发展阶段演进（2018–2026）",
  "stages": [
    {
      "id": "s1",
      "name": "S1 · 起源：任务被经典前驱定义",
      "period": "2018–2020",
      "driver": "实时设备需求把『只要目标说话人』拉起来",
      "works": [
        {"label": "time-domain SpeakerBeam", "type": "pre", "year": "2020"},
        {"label": "PercepNet", "type": "pre", "year": "2020"},
        {"label": "Personalized PercepNet", "type": "this", "year": "2021"}
      ],
      "breakthrough": "TSE 由 enrollment 条件化定义；时域/感知两条骨架分别定型",
      "gap": "目标条件化与实时低复杂度尚未统一"
    }
  ],
  "stage_edges": [
    {"a": "s1", "b": "s2", "label": "转向：个性化 + 实时低复杂度整合"}
  ]
}
```

**author 纪律**：
- 阶段数 **3–5**；`name` 给"定性句"（起源/骨干定型/主流成型/分岔/前沿），不要只写序号。
- `driver`（推动力）写**为什么**变（外部需求/骨干被引入/评测挑战/瓶颈引爆），**不是**流水账。
- `works` 每阶段 **1–3 个代表**就够：库内标 `type:"this"`（实心金），库外按角色标浅色；label ≤2 行短名+年份，**别带指标**。
- `breakthrough` / `gap` 用**阶段级结论**（这段整段突破了什么/留了什么），≤1 行半；**禁止**逐篇列数字。
- `stage_edges` 只在**相邻阶段**之间画一根，标签是"转向词"，不是关系清单。
- 别把 G1 画成方法继承图——继承细节是 G2 的事；G1 只讲"时间与阶段"。

## G2 fig:"family" 家族泳道图 —— JSON 与设计纪律

家族泳道图是"分岔结构"的配图：每条技术家族 = 一条横泳道，道内节点按血缘/时间从左到右成链（实线=道内继承），跨家族关系画带编号虚线，解释在图下边注表。

```json
{
  "fig": "family",
  "title": "TSE 技术家族分岔与跨族借用",
  "intro": "三大家族各占一条泳道；虚线带编号 = 跨族关系（只画相邻泳道，见边注表）。",
  "lanes": [
    {
      "id": "fam_ppn",
      "name": "A · 感知特征条件化\n48k 实时个性化增强",
      "nodes": [
        {"id": "percep", "label": "PercepNet\n2020", "type": "pre"},
        {"id": "ppn", "label": "Personalized PercepNet\n2021 库内", "type": "this"}
      ],
      "edges": [
        {"u": "percep", "v": "ppn", "label": "最小侵入改造"}
      ]
    }
  ],
  "cross": [
    {"from": "fam_ppn.ppn", "to": "fam_ss.x", "label": "邻域对照",
     "note": "同任务不同路线，互列对照链", "evidence": "PPN §6.3"}
  ],
  "cross_notes": [
    {"label": "邻域对照（A 与 C）",
     "note": "A、C 泳道不相邻，虚线会横穿 B，不画；语义与相邻边同类（正文处理）",
     "evidence": "PPN §6.3 / …"}
  ]
}
```

**author 纪律**：
- 家族数 **2–5**；`name` 带约束/擅长关键词（如"时域状态空间 · 16k 轻量实时"），便于读者快速分道。
- `lanes[].nodes` **从左到右 = 血缘/时间序**（前驱在左、现役/库内在中、下游在右）。库内 `type:"this"`；库外按角色。
- `lanes[].edges` 只画**道内**有实际继承意义的边（改造/承接/同源）；纯并列不画。
- `cross[]` 才是跨家族戏份：**模块来源 / 直接竞品 / 邻域**。每条给 `from`/`to`（`道id.节点id`）+ 短 `label`（关系词）+ `note` + `evidence` → 渲染器自动编号（虚线）并生成**边注表**。
- **跨族虚线只画上下相邻的泳道**：`from`/`to` 所在道索引差 `|Δ|=1` 才画线，渲染器会在出/入点取两框相对一侧的框边、**走框外不压字**；若 |Δ|>1（中间隔了别的泳道），把关系挪进 **`cross_notes`**（label/note/evidence）→ 边注表末尾记〔文字·未画线〕，图上不画。
- **道内节点每族 ≤5**、`cross + cross_notes ≤8`。放不下：只画"离主线最近的一跳"，其余进正文/索引。
- 评测/综述类锚点（R5）通常不开新道、不强行入链——放进正文或索引即可。
- 同源衍生对（学位论文↔期刊版）放同族相邻，道内边标"同源衍生"。
- 图内文字**别用 `↔`**（Microsoft YaHei 缺字形，U+2194 → 豆腐块）；需要"双向/对照"写"与/对"，箭头在 mermaid/正文写。

## G3 fig:"quad" 机会象限图 —— JSON 与设计纪律

G3 从 v2.0 的 pa_fig scatter（x=方法成熟度低→机会，易歧义）改为**自带 quad 象限图**：横轴改叫「机会空间 / 空白度」，**越右 = 越没人系统做过**；纵轴「前沿活跃度」，越高越热。右上 = 又热又空 = 最该投。

```json
{
  "fig": "quad",
  "title": "G3 · 机会象限图：空白度 × 前沿活跃度（右上 = 又热又空 = 最该投）",
  "sub": "坐标 0–1 仅供示意。判据（为什么『空白大=机会大』）：越往右越没人系统做过——①无共享可跑基准；②关键主张无严谨复核/同表数据；③现役×现役交叉无人试；④缺开源实现与真机实测。",
  "x": "机会空间 / 空白度", "y": "前沿活跃度",
  "x_lo": "已有人系统做", "x_hi": "没人系统做（空白大）",
  "y_lo": "冷 · 少人问", "y_hi": "热 · 正当红",
  "quad": {"tl": "又热已满\n拼执行", "tr": "又热又空\n最该投",
           "bl": "又冷又满\n可不用追", "br": "空但冷\n早留意/布局"},
  "foot": "点=机会子题（正文 §4.3）；越靠右上越该投。",
  "points": [
    {"id": "O1", "label": "O1 三方横评", "x": 0.8, "y": 0.86, "note": "…"}
  ]
}
```

**author 纪律**：
- **消除「空白多」歧义是第一位**：`sub` 必写空白度判据（四条可勾选），`x_lo/x_hi/y_lo/y_hi` 给两极端语义。
- 点的 (x,y) 是 0–1 示意值：要**让正文读法与坐标一致**（说"右上区 = O1/O2/O3"，就真的把它们放在 x>0.5,y>0.5；说"O5/O6 偏冷"，就放 y 小）。坐标≠精确测量，`foot` 点明。
- label 短（≤9 字/个点）；别让点压住象限区中心的小字区标（点别停在 (0.25/0.75 附近) 的区中心上）。
- 六七个点就够；点不带 emoji、不用 `★`。

## G4 fig:"audit" 生态盘点矩阵 —— JSON 与设计纪律

G4 是把「从更多方面跟进方向」落成一张可读的盘点矩阵：回答"生态里谁做了、各用什么协议自证、复杂度口径怎么各说各话"——**能比什么、不能比什么一目了然**。行=方法（粗黑带=研发谱系），列分三组（方法 / 评测协议 / 复杂度口径）。

```json
{
  "fig": "audit",
  "title": "G4 · 实时 TSE 生态盘点矩阵：谱系带 × 评测协议 × 复杂度口径",
  "sub": "行=方法，粗黑带=研发谱系，金实=库内。三带协议互斥→只能带内并排。",
  "col_groups": [
    {"label": "方法", "cols": [0]},
    {"label": "评测协议 · 主指标（跨带不通约）", "cols": [1, 2, 3]},
    {"label": "复杂度 / 实时口径（不可换算）", "cols": [4, 5, 6]}
  ],
  "cols": [
    {"label": "方法（谱系内现役）", "key": "nm", "w": 2.0},
    {"label": "带宽 / 域", "key": "bw", "w": 1.4},
    {"label": "主指标", "key": "metric", "w": 2.0}
  ],
  "bands": [
    {"name": "甲 · …组 —— …系（48k，带内只有自比）",
     "rows": [
       {"name": "…", "type": "this",
        "cells": {"nm": "PPN-512\n2021 库内", "bw": "48k 感知域",
                  "metric": "PESQ 2.357 / MOS 3.128", "…": "…"}}
     ]}
  ],
  "note": "读法：①…②…③…（诚实标注哪些同表可比）",
  "legend_tail": "粗黑带=谱系 · 金实=库内 · 浅虚=锚点未读"
}
```

**author 纪律**：
- **诚实纪律是本图的灵魂**：评测协议互斥（PESQ/MOS、SDR/DNSMOS、SI-SDR 三种刻度）与算力单位互斥（%CPU / RTF实测 / MACs）**如实并排**，并在 `note` 写明"只有带内同协议的行才可排序、给唯一可排的例子"。
- `bands` = 研发谱系（行按谱系分带）；带内可有同表竞品（注明他组锚点未读），等于把"谁在这个 Table 上比过"画出来。
- `cols[i].w`（英寸）由作者给：窄格会自动换行、行高自适应，但**别把 5+ 行文字塞进一格**；第 0 列是方法名（粗体自动）。无数值、只给目标值的下游方法（UPN/Dual-Mode/AR-BSNet…）**不入表**，作文字（见 G1/G2）。
- 一个方向一张 G4 就够；行数控制在 6–10，band ≤4。
- `note` 的四句读法必须直指 §4 的"评测桶/复杂度口径"瓶颈，形成证据闭环。

## T1 fig:"terrain" 学科地形图（学科级）—— JSON 与设计纪律

T1 是把**学科级论断**落成一张可读的地形图：行=一个细分方向（分带：`库内已建目录` / `论断新增候选`），列=成立度 / 成熟度 / 活跃度 / 空白度 / 库内样本 / 边界一句话。**色深 = 该维取值高**（低/中/高三档）。判法（四要素口径、样本不足纪律、新开一刀的证据门）见 `discipline-method.md`。

```json
{
  "fig": "terrain",
  "title": "T1 · 学科地形图：语音与音频信号处理（细分方向论断）",
  "sub": "行=细分方向（带内按成熟度降序）；色深=该维取值高（低/中/高）；成立度三色；库内不足 2 篇的行标「样本不足·推断」。",
  "cols": [
    {"label": "细分方向", "key": "name", "w": 3.4},
    {"label": "成立度", "key": "standing", "w": 1.15, "kind": "standing"},
    {"label": "成熟度", "key": "maturity", "w": 2.6, "kind": "level", "hue": "#5b9bd5"},
    {"label": "活跃度", "key": "activity", "w": 2.6, "kind": "level", "hue": "#e0645a"},
    {"label": "空白度", "key": "blank", "w": 2.6, "kind": "level", "hue": "#6fbf73"},
    {"label": "库内样本", "key": "n", "w": 1.7},
    {"label": "边界一句话", "key": "boundary", "w": 3.4}
  ],
  "bands": [
    {"name": "库内已建目录", "type": "this", "rows": [
      {"name": "目标说话人提取与语音分离（TSE）", "standing": "成立",
       "maturity": {"level": "高", "why": "骨干与协议已收敛（3 篇可两两对照）"},
       "activity": {"level": "中", "why": "近两年仍以换骨架为主"},
       "blank": {"level": "中", "why": "评测协议三刻度互不通约"},
       "n": "3 篇 ｜ 1 份方向综述",
       "boundary": "与 SE 的边界：是否引入说话人条件"}
    ]},
    {"name": "论断新增候选（待补证据）", "type": "next", "rows": [
      {"name": "候选：…（未建目录）", "standing": "存疑",
       "maturity": {"level": "不详", "why": "库内无已分析报告"},
       "activity": {"level": "不详", "why": "未做库外检索，不得计入论断"},
       "blank": {"level": "不详", "why": "同上"},
       "n": {"text": "0 篇 ｜ 样本不足·推断", "color": "#c0392b", "bold": true},
       "boundary": "与 TSE 的边界：多说话人 vs 单目标"}
    ]}
  ],
  "conclusion": "学科级一句话论断（方向数 <3 时必须写成「本库目前只铺开这几块」并标样本不足·推断）",
  "note": "读法 + 证据门一句（库外检索只进待读候选）"
}
```

**column kind 三选一**（决定画法）：
- `text`（缺省）：逐格排文本、自动换行；第 0 列自动粗体。值可写成 `{"text","color","bold"}` 强调（如样本不足的红字）。
- `standing`：成立度胶囊（绿=成立 / 黄=部分成立 / 红=存疑，未知色走灰）；取值就是 `成立|部分成立|存疑`。
- `level`：**分级格**——格内画两级条（浅底 + 按 低 0.33 / 中 0.66 / 高 1.0 填充的深条）+ 等级字 + 下方 `why` 一行小字；需给 `hue`（每维一色：成熟度蓝 `#5b9bd5` / 活跃度红 `#e0645a` / 空白度绿 `#6fbf73`）。值必须是 `{"level":"低|中|高|不详","why":"…"}`，**`why` 只写一行判据**（完整论证进正文）。

**author 纪律**：
- **切法先行**：行先按 `discipline-method.md` §二 四条判据定下来再画；「实时/轻量/低资源」这类**约束不许占一行**（它们进 `why` 或 `note`）。
- 带内**按成熟度降序**排（先成熟后新芽）；新刀（未建目录的候选）单独进「论断新增候选」带，且只有**过门**的才进图。
- **`不详` 是合法档位**，不是缺陷：证据不足就填 `不详` + `why` 写明为什么不足，**不许猜档**；正文标「推测」的格，图上不能反而更硬（见 discipline-method §八）。
- 样本不足的行：样本列写成 `{"text":"n 篇 ｜ 样本不足·推断","color":"#c0392b","bold":true}`，与正文标注一致。
- `conclusion` 是**必填**（ds_render 会拦）：一句话学科级论断，不允许只复述表格内容。
- 行数控制在 4–8、带 ≤2；边界一句话 ≤18 字（超了就在图上换行、更容易压叠，也会稀释读法）。
- 每维格子密度要**能被一眼比较**：同一列的 `why` 长度尽量接近（1 行），长句进正文。

## 图读法 + 边注表：每张图的解释结构

**图读法块**（每图必配，紧跟图下；结构固定）：
1. **这张图回答**：一句话（读者的预期）。
2. **符号**：颜色/线型/画布概念一句话（谁实心、谁虚线、带/道/象限/矩阵怎么读）。
3. **怎么读（3 步）**：先看什么建立骨架 → 再看什么找细节 → 最后得出什么结论。
最后一句落到"下图/正文哪节"或"哪些东西图上故意没画、去哪看"。

**G2 边注表**（随图放，表格式）：
`| 编号 | 从 → 到 | 关系 | 依据/出处 |`
编号与 `[k]`（画线）对应；`cross_notes` 里的文字边记作 `[k]〔文字·未画线〕` 排在表末。让"图 = 结构，表 = 证据"，图就不脏。

**示例（图读法，G2）**：
> **图读法（G2）**——这张图回答"现在岔成几股、每条血缘、谁和谁邻域对照"。三条泳道即三大家族：感知条件化（A）、时域 SSM（B）、T-F band-split（C）。金色实块=库内已分析，浅虚块=库外未读锚点；实线=道内继承，虚线带编号=跨族关系（只画相邻泳道）。怎么读：①看几条泳道与最右端现役节点 → 分岔结构立现；②沿每道读链 → 每族"前驱→现役→下游"清楚；③查编号虚线对照下方边注表 → 看懂 B 夹在中间，A↔B、B↔C 画线、A↔C 因隔层 B 而作文字边。图上没画"未同表对比"的关系——那没证据，见 §6 缺口。

## 几何红线（无预览时代替肉眼）

本机无 PNG 预览 → 必须**程序化几何自检**，不靠肉眼。自检已**内置在渲染器**：出图命令加 `--qa`（`ds_render.py --qa` 透传给 `ds_fig.py --qa`），`Figure.save` 前遍历所有 `ax.texts` 的 window_extent→data 坐标，文字出 (0,W)×(0,H)（容差 0.02）或两两重叠面积 >0.002 sqin → 逐条列出，**退出码非 0 拦下**；通过则打印「几何 QA 通过」。改动数据/换字体后一律重跑 `--qa`。
1. **箭头/虚线不穿框、不出框内**：出/入点取两框相对一侧的框边（对方在下方→出下边进上边；在上方→出上边进下边），弧线走框外。渲染器已按此实现；改数据后 `--qa` 复检。
2. **文字不出画布、两两不压叠**：交给 `--qa`（实现见 ds_fig `_geometry_qa`；不要退回「肉眼/临时脚本」）。
3. 字体/字形：图内文字**不用 emoji**（ds_render 会先拦）、**不用 `↔` 等 YaHei 缺字**（U+2194）；换 font 后重跑一次 `--qa` 看 warning。
4. 一个数据单位 = 1 英寸；行高/列宽用 `Measure.wrap/ext` 量宽，排版按量出的高度推进（audit 尤其），避免头/行压叠——压叠也由 `--qa` 兜底。

## 常见坑（把图搞乱的做法）
- ❌ 边标签写长证据（"竞品+模块·Table2 同表+大窗过参数化来源 §5 R2 引[8]"）→ 只写"模块来源"，出处进边注表/正文。
- ❌ 把阶段与论文画成同一种框 → G1 用阶段带、G2 用泳道，画布概念别混。
- ❌ 25+ 节点、跨 4 层长边、所有锚点平铺 → 砍到"结构可读"的最小集。
- ❌ 图里塞 `★⚠✅↔` 等符号 → 豆腐块；星级/符号留在正文表，图用颜色/文字。
- ❌ 跨族边连到隔了两层泳道的节点（虚线横穿中间泳道压字）→ |Δ|=1 才画线，否则进 `cross_notes` 文字边。
- ❌ 箭头出/入点取"远侧翻转"导致弧线穿框压字 → 出/入点取两框相对一侧，走框外。
- ❌ G3 坐标与正文读法打架（正文说右上、坐标却在左上）→ 先定 O 点坐标再写读法，写完后对一遍。
- ❌ 每阶段 works 挂 6 个代表 / 每族塞 9 个节点 → 只留"讲清结构需要"的 1–3/≤5 个。
- ❌ 图放一处、解释在几页后 → 图读法必须紧跟图。
- ❌ **T1 把约束当方向**（"实时 TSE""轻量化 SE"各占一行）→ 约束进 `why`/`note`，行必须是独立任务块。
- ❌ **T1 用色深掩盖证据不足**：库里只有 1 篇却填「成熟度高」不加样本标注 → `不详` + 「样本不足·推断」，纪律见 discipline-method §五。
- ❌ **T1 把库外新检索当论断证据**（拿 S2 检索结果直接判空白度高）→ 新检索只进待读候选，不参与打分。
- ❌ T1 `why` 写成长句/多行论证 → 每格一行判据，论证进正文 §3。
