# 前沿 · 瓶颈 · 机会判读法（opportunity-method）

## 一、前沿关注点怎么判
「前沿」= 最近 1–3 年在推、方法上仍活跃移动的子问题。判据（命中越多越稳）：
1. **锚点聚集**：多篇已分析报告 §5 的「R4 后续演进 / 直接竞品」指向同一批论文 → 那一带就是当前活跃点。
2. **年份聚集**：同一子主题的锚点年份集中在近 1–2 年。
3. **库外新信号**：库外锚点标题里出现的新词（复数谱、跨模态、低资源、因果实时、状态空间…）——标注是哪篇报告引它、引在哪个语境。
4. **论文原文自述**：报告「拓展方向/Conclusion」里作者预告的方向，通常也是前沿感最强处。

**写法**：给 2–4 个前沿子题，每个一段：在推什么（谁/哪年/几篇）→ 为什么算前沿（证据）→ 卡在哪（引出瓶颈）。

## 二、发展瓶颈怎么分
按三桶分，避免全是技术桶：
| 桶 | 判据 | 例子 |
|---|---|---|
| 技术 | 报告 §4 批判高频命中（因果实时/跨语种/低 SNR 稳定性/复杂度过高） | 状态空间长程依赖、频带数爆炸、相位估计弱 |
| 数据 | 资源清单 ⛔/☐ 的数据（受限、未开源、缺跨语种语料） | VB/LDC 需授权、中文低 SNR 自建数据未开源 |
| 评测 | 指标口径分裂、无统一 benchmark、单一语种评测 | STOI 宽/窄带混乱、只测合成噪声 |

每条标：**严重度**（高/中/低）+ **是否可绕行**（绕行办法一句，如「换公开近似集」「自建评估集」）+ 依据（哪篇报告哪节）。

## 三、机会与新方向怎么给
**3–6 个候选**，每条四要素：
1. **方向名**（一句话，可带英文）
2. **建议做法**（怎么干：新骨干？新损失？跨方向嫁接？）
3. **切入点**（挂库内哪篇：它的短板/遗留问题即入口）
4. **预计贡献 / 需要的资料**（联动各篇「资源清单」缺口）

**来源**（按优先级）：
- 库内报告 §4.4 改进建议 + §5.1 拓展方向的**共同指向**（多篇同向 = 更强机会信号）；
- 瓶颈表中「严重度高且可绕行」的项 → 天生是机会；
- 库外锚点的「下一代该长什么样」推断——**只做推断、不编已有论文**；
- 未分析 PDF 若贴切，放这里当「待读候选」先行验证（见五）。

**表达**：正文按 4 要素写每条；图用 **G3 机会象限（quad）**——x=机会空间/空白度（**越右=越没人系统做**），y=前沿活跃度（越高越热），**右上=又热又空=最该投**。点坐标 0–1 只示意（别伪装精确测量），**正文读法要与坐标一致**（说"O1/O2/O3 在右上"，就真放 x>0.5,y>0.5）。

**空白度判据（为什么『空白大=机会大』，写进 G3 的 sub 消歧）**——越往右越该满足下面几条，命中越多空白越大：
1. **无共享可跑基准**：这个子题没有公开统一评测集/复现路径，各家自报无法对比；
2. **关键主张无严谨复核/同表数据**：核心卖点只在一篇论文上验证过，没有独立复核或同表竞品；
3. **现役×现役交叉无人试**：两个当红骨干/路线各有独立论文，但没人把它们组合/互作基线试过；
4. **缺开源实现与真机实测**：只有仿真/只有训练端结论，没有开源代码与设备端（低功耗/ARM/实时)实测。
> 纵轴（活跃度）与横轴（空白度）正交：一个子题可以又热又空（右上，最该投）、也可以热但已满（左上，只剩拼执行）。别把「少人做」直接当成「值得做」——又冷又空（右下）需先判冷是「没人注意」还是「已验证走不通」。

## 四、证据格式与「待核」纪律
- 正文里每条判断尾注来源，如 `（依据：SE-VMamba 报告 §5 R4；SE-VMUnet++ 报告 §4.4）`。
- 没证据 → 句首写「（推测）」并进 §7 待核清单。
- **红线**：不编造库外论文的存在/年份/指标；不把未读当已读；不确定就 `年份?` /「待核」。

## 五、未分析 PDF → 待读候选
- 未分析 PDF 只出现在：§5 机会的「待读候选」小节 + §6 待读队列，**不进档案/横评/图**。
- 给一行：文件名（缩略题）→ 可能补哪个机会/堵哪个缺 → 建议优先级。
- 若库内已分析论文明显引用某未分析 PDF 作为基线 → 特别标出「建议优先分析（作基线对照）」。
