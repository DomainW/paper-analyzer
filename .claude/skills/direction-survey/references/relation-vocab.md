## 节点类型（身份 + 角色配色）
| type | 身份/含义 | 在两张图里 |
|---|---|---|
| `this` | **库内已分析论文**（实心金） | G1 阶段代表、G2 家族主力节点都优先给金色实色 |
| `pre` | 库外锚点·上游前驱 | 谱系最左、绿 |
| `rival` | 库外锚点·直接竞品 | 常作跨族竞品，红 |
| `module` | 库外锚点·模块/子技术来源 | 常作跨族借用来源，蓝 |
| `next` | 库外锚点·后续演进 | 谱系最右、紫 |
| `adj` | 库外锚点·细分邻域/评测/综述锚 | 一般不建节点强入链，进正文/索引，灰蓝 |
| `generic` | 阶段带/泳道等画布元素 | G1/G2 不使用该型节点（阶段带与泳道是画布概念） |

> 一个锚点从多篇报告 §5 分别出现且角色不同：节点取一个**相对方向主线**的主角色（正文注明它同时是另一篇的 X）。

## 图内边标签：短标签规则（v2 关键）
图上空间最贵。**边标签只放「关系动词 + 极短出处」**，例：
- 道内继承：`继承·最小侵入改造` / `同源衍生` / `承接`（可不带出处，道内看图即懂）。
- 跨族借用（走 `cross`）：`模块来源` 或 `直接竞品` + 出处压缩如 `§5 R3`，一句人话写进 `note`，证据写进 `evidence` → 汇成**边注表**。
- 禁止把证据整句塞进图（如 `竞品+模块·Table2 同表+大窗过参数化来源 §5 R2 引[8]`）。

## 边关系词表（落到边注表/正文）
| 关系动词 | 含义 | 典型来源表述 |
|---|---|---|
| 前驱 | B 的核心技术源自 A | §5 R1 上游主干；演进树 A 在 B 前 |
| 同源衍生 | 同课题组/同体系期刊版↔学位论文/前作后作 | 馆藏清单同作者注记 |
| 直接竞品 | 同任务同期可同表对比 | §5 R2；批判基线表收录对方 |
| 模块来源 | B 某组件直接借自 A（可跨域） | §5 R3 |
| 后续演进 | A 之后的发展/被超越 | §5 R4；citations |
| 邻域补充 | 旁支、评测锚、不同切法 | §5 R5；v2「补充/邻域」 |
| 复现/对照 | 库内实际复现对方 | 复现/README |
| 被超越/反超 | 横评同表 A 压过 B | 同一横评表数值 |

样式：道内继承 **实线**；跨族借用/涉及库外锚点 **虚线**；「推测」虚线 + 前缀 `（推测）` 并入缺口。G2 跨族虚线由渲染器**编号**，解释看边注表。

| v3 角色 | 综述边 | v2 报告对应表述 |

| R1 上游主干前驱 | 前驱 | 「方法源头/同源前作」 |

## 家族（lane）划分与归口
家族是 v2 叙事的一级对象，切法建议：
1. 先找**技术主干**：按骨干/表示域/实时策略分（如 TSE = 感知特征条件化 / 时域 SSM / T-F band-split）。
2. 库内每篇与主要锚点归到**恰好一个家族**（同源衍生对同族相邻）；同一锚点被两族引作不同角色 → 放其在主线相关的家族，另一角色在正文/边注表补。
3. 家族间真正的**技术借用**才进 `cross`；只是"同任务并列"不画边。
4. 家族名尽量 = 「族关键词 + 约束/擅长」，如「时域状态空间 · 16k 轻量实时」，让读者不看正文也能分道。

## 库内 vs 库外锚点 的呈现
- 库内已分析 = 金色实色；正文给索引行、图读法里点出"哪篇是库内主力"。
- 库外锚点 = 浅色虚线框 + 标「未读」；不给假指标；正文只给「角色 + 报告出处 + 已知年份（缺则 `年份?`）」。
- G1 图例、G2 图例都统一注明「金实=库内已读；浅虚=库外未读锚点」。
- 身份色只作用于 **G1/G2 的节点**；G3 quad 的点**不带身份色**（只编号+标签，身份讲在正文）；G4 audit 的行用 `type` 画**金实身份条**（`this`=库内）或浅虚锚点条——语义细节见 figure-design.md 的 quad/audit 节。

## 去重 / 同源规则
1. 同一工作被多篇报告 §5 收录 → 合并为一个锚点节点，edges 保留各出处。
2. 库外锚点已在库内被分析 → 提升为库内节点（金实色）。
3. 学位论文 ↔ 衍生期刊预印本 → 两个库内节点，同族相邻，边标「同源衍生」，正文说明增量位置。
4. 同一家族内的前驱/衍生链不重复画两遍：G1 讲时间、G2 讲结构，各画一遍即可。

## 缺元数据 / 查不到边的处置
- 缺年份/venue → `年份?`；缺作者 → 略。
- 两库内论文/两家族该连但报告没给明 → 缺口列「待核边：A ↔ B」，**不靠猜画边**。
- v2/v3 报告混用致篇目不全 → §1 口径明示，缺的库内篇目算缺口。
