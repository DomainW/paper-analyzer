## 路径规范（v4.1.0 — 与论文库结构联动）

仓库以 `论文库/` 组织（见仓库根 `README.md`；**改结构前必须同步两侧**）：

| 角色 | 路径 |
|------|------|
| 候选扫描入口 | `论文库/**/未分析/**/*.pdf`（递归，含 `论文库/_未分类/未分析/`） |
| 归档出口 | `论文库/<学科>/<方向>/已分析/<发表年>/<论文名>/` |

**发表年分层（v4.1.0 新增）**：细分方向内的 `已分析/` 下先按**论文发表年**分文件夹，再放论文文件夹——
- `发表年` = **正式出版年**：会议论文取会议年、期刊论文取卷期年、学位论文取**答辩年**；尚无正式出版的预印本/投稿稿暂用其稿面年份；确无据 → `年份不详/`。**不臆造**，年份出处写进报告 §1「年份 / venue」行。
- 年份文件夹名 = **四位数字**（如 `2020/`），不写"年"字；同年多篇并列其下。

**每篇论文一个独立文件夹**，布局如下（**默认只建 `原文/ 分析/`**，其余按需）：

```
已分析/<发表年>/<论文名>/
├── 原文/           PDF + 提取文本(.txt/-layout.txt/-health.json)
├── 分析/           报告 .md（+ .docx 按需）+ 两图(.png) + 图 JSON
├── 复现/           我们亲手跑的代码 + 笔记（按需）
├── 数据/           实验数据集；下载脚本放 数据/下载脚本/（按需）
├── 资料/           官方代码镜像/权重配置/评测脚本/补充（按需）
│   ├── official-代码/ · 权重配置/ · 评测脚本/ · 补充/
└── 资源清单.md     复现资料六类分类收集清单 + 状态跟踪（步骤 6 · 按需）
```

- 学科/方向：由 PDF 所在路径自动推导；位于 `_未分类` 时先用 AskUserQuestion 询问。
- 报告命名：`<论文名>-分析报告.md`（`.docx` 按需）；图命名 `<论文名>-<图名>.png`。
- 论文文件夹名规范 = 英文原题（中文译题），见根 README「分类与命名规范」。

## 工作流（TaskCreate 建任务跟踪）

```
进度（默认路径 = 报告线；带 ◇ 的两步是按需分支，默认不做）：
- [ ] 步骤 0: 确认分析目标（多 PDF 选择）
- [ ] 步骤 1: 读取 PDF——分层抽取 + 页面体检（pa_extract.py + Read 视觉补读）
- [ ] 步骤 2: 核心逻辑分析（背景/创新/方法论脉络/论证链）
- [ ] 步骤 3: 关键公式与验证步骤提取
- [ ] 步骤 4: 批判性分析五段（必扫清单→判定表≥8条→致命一击→核验就地登记→Top3小结）
- [ ] 步骤 5: 多库搜索 5 篇分角色相关论文（MCP + pa_query.py）
- [ ] 步骤 7: 生成 Markdown 报告 + 渲染两图（templates/report-v4.md，arch + rel）
- [ ] 步骤 8: 归档（按发表年 mv 入 已分析/<发表年>/<论文名>/ + 更新馆藏清单）
- [ ] ◇ 步骤 6:【按需】代码与数据溯源 → 建 复现/数据/资料 + 写 资源清单.md(六类初稿)
- [ ] ◇ 步骤 8b:【按需】转 Word（pandoc + TOC）
```

> 串行纪律：步骤 0→1→5→7→8 依赖外部/前后产物，**严格串行**；
> 步骤 2/3/4 基于同一份全文，可在思考中并行完成，不必外部工具。
> **默认不执行 ◇ 两步**（省 token）：只有用户点名"要复现资料 / 建资源清单 / 转 Word"时才补做，步骤编号不变。

## 三种执行模式（先判定再走流程）

收到请求先判模式，**别一上来就全流程**：

| 模式 | 触发 | 执行 | 产物 | 归档 |

## 步骤 2：核心逻辑分析

### 2.1 背景应用与研究问题
- 实际应用场景 / 现有方法核心瓶颈（≤3 条）/ 研究问题一句话。依据：Intro+Abstract（标注章节）。

### 2.2 核心创新点（含金量评级）
| 创新点 | 本质区别（vs 谁） | 创新类型 | 含金量 | 为什么重要 |
评级：★★★★★ 范式转移 ｜ ★★★★☆ 突破性创新 ｜ ★★★☆☆ 改进型 ｜ ★★☆☆☆ 应用型。
> ⚠ **表格里的竖线必须转义**：单元格内的绝对值/基数竖线（`\|P\|×\|F\|`、`ρ=\|SM(e,j)−SM(i,j)\|/SM(e,j)`）一律写作 `\|`——**不转义会让该行切出多于表头的格数，超出表头的单元格被渲染器（GFM 与 pandoc/docx）直接丢弃 → 含金量 / 为什么重要 等靠右列整列静默消失，而 md 源看起来完整**。**两处配套细节**：① **别把竖线留在行内代码段里**——`` `b = \|x\|` `` 的反斜杠不被解析，docx 里就是可见的 `\|x\|`（含竖线的那处不包反引号，写普通文本 `b = \|x\|` → docx 得 `b = |x|`）；② **数学环境内另有坑**：`$…\|…$` 的 `\|` 被 pandoc 当 LaTeX `\Vert` 渲染成 ∥（U+2225），而 `\vert` / `\lvert` 其 markdown 读入器又不认——**把竖线移出数学环境**，写成 `$1 \ldots$ \|F\|`（docx 中即 `1 … |F|`）。**同理，普通文本里的「反斜杠+字母」（`\x`、路径 `C:\Program`）会被 pandoc 当 LaTeX 控制词吃掉**（实测 `|y\x|` → `|y|`）：双写 `\\x`、或路径用代码段包住。完成线会跑 `_工具/table_check.py` 复查（两类都查）。
**如实降权**：哪些是迁移/组合要写明，别全标"首创"。

### 2.3 方法论脉络（文字）
- 用一段文字交代前驱 → 本文 → 推测后续（各给出处）；**不再画演进树/脉络图**——方向的阶段演进与家族分岔归 direction-survey 方向综述（G1/G2），单篇报告只留 §3.1 架构图 + §5.3 关系图两张。
- 技术大类判断：深度学习→时域/时频/端到端；统计→贝叶斯/优化；实验科学→验证/仿真。

### 2.4 论证链
前提假设（内容/依据/强度：强中弱）→ 推论（推导/验证 Table X/强度）→ 主要结论（证据/强度）→ **最薄弱环节**（衔接 §4）。

### 3.1 技术架构

## 步骤 4：批判性分析（v3.2 五段：先广后深、可排级、挂核验）

总纲 `references/critical-review-framework.md`（CERIC + Nature 审问 + 严重度/置信度/核验口径）；逐项扫雷 `references/critical-failure-modes.md`（语音/ML 必扫清单）。产出五段：

2. **4.2 不足点判定表（核心）**：汇 必扫命中 + CERIC/审问挖出的点，每行 = 类别(声称/方法/实验/论证/写作/复现)·具体不足(原文位)·严重度(致命/重要/一般)·置信度(高/中/低)·核验(可核验·类N / 查不动·原因 / 纯文本)·改进建议(一句最小动作)。**每篇 ≥8 条**，含 ≥1 条方法/实验级硬伤。
3. **4.3 致命一击**：对论文**最强主张**给最强反驳（2–4 句论证 + 作者可能辩护 → 为何仍不足 + 需补的最小实验），承接 §2.4 最薄弱环节。
4. **4.4 可核验性**（默认**就地登记在报告内**）：「可核验」注明要用哪类资源核（类2代码/3数据/4权重/5评测/6环境）；「查不动」且影响判定 → 本表写清"待核什么 + 怎么核"。**默认不挂 `资源清单.md`**（该文件按需才有，步骤 6 未跑时不存在）；确有 `资源清单.md` 时再同步加 §7 `- [ ]`。
5. **4.5 批判小结**：按 严重×置信×可修 排 **Top-3 缺口** + 整体可信度评级（基本可靠 / 部分可靠待验证 / 关键硬伤），Top-1 **回填速览卡"最大短板"**。
> 批判≠挑刺：给边界条件与适用前提，每句有原文页码/表号/公式；找不到依据标置信度"低·待核"，不空写。

### 5.1 五类"脉络角色"（各选一篇，避免同质 top-5）

|------|--------|---------|--------|

3. **更新 `论文库/README.md` 馆藏清单**（删除未分析条目、登记已分析行，路径带发表年层）。
4. 向用户汇报：归档路径（含发表年）、报告要点、两图、以及**本次未做的按需项**（docx / 资源清单 / 复现目录——留一句"需要就说"）。
5. **◇ 8b 转 Word（仅用户要求时）**：见 `references/docx-generation.md`。
   ```bash
   cd "<分析>"                                    # 关键：保证相对图片路径可用
   pandoc "<论文名>-分析报告.md" -o "<论文名>-分析报告.docx" \
     --from markdown --to docx --toc --toc-depth=2 \
     --metadata title="<论文名> — 深度分析报告"
   ```
   > 仅文字/表格兜底时才用 docx npm 包（不带图/公式）。

## 重要提醒（v3）

### 质量控制
1. **质量优先**：宁可深析一篇，不泛谈；每个判断有原文依据（标注页码/章节）。
2. **指标与公式必核对原文页**；自动抽取的表格必须复核再入报告。
3. 相关论文 **方法论相似 + 分角色**，不只"同领域"；每篇写明"为什么像 + 与本文实际关系 + 证据"。
4. 批判=先广后深：failure-modes 逐项过（无空行）→ 判定表 **≥8 条含 ≥1 硬伤** → 致命一击 → Top-3 回填速览卡最大短板；客观评估不挑刺，每条带原文位。
5. **默认产物纪律（v4.1.0）**：默认只出 **md 报告 + 两图**，归档进 `已分析/<发表年>/<论文名>/`。**不要顺手**多出 docx、`资源清单.md`、`复现/ 数据/ 资料/`——用户点名才做（省 token）。若确做了按需项，报告里才可引用它们。
6. 代码/数据"官方 vs 第三方"严格区分；许可分代码/数据/权重记录（仅在做了按需的步骤 6 时才收集记录）。
7. **表格竖线必转义**：单元格内绝对值/基数竖线写作 `\|`。不转义 → 该行列数多于表头 → **超出表头的单元格被渲染器直接丢弃**（含金量 / 为什么重要 等靠右列**静默整列消失**，md 源看不出）。① **含竖线的那处不要包行内代码段**——代码段按字面输出、反斜杠不被解析，docx 里会出现可见的 `\|x\|`；② **数学环境内不能用 `\|`**（LaTeX 的 `\|` = `\Vert` → ∥；`\vert`/`\lvert` pandoc 的 markdown 读入器亦不认），应把竖线移出数学环境：`$1 \ldots$ \|F\|`；③ **普通文本里的「反斜杠+字母」会被 pandoc 当 LaTeX 控制词吞掉**（`|y\x|` → `|y|`、`C:\Program Files` → `C:Files`）——双写 `\\x` 或用代码段包住。收尾按完成线跑 `_工具/table_check.py`（两类都查）。

### 工具执行
8. TaskCreate 建步骤跟踪（默认路径 7 步 + 2 个 ◇ 按需步骤），逐步 TaskUpdate。
9. Semantic Scholar MCP 工具名随版本可能变化，调用前查可用工具；搜索严格串行。
10. MCP 不可用/限速 → 回退 `pa_query.py`(OpenAlex/arXiv/DBLP) + GitHub；仍缺 → WebSearch。
11. 图表：每篇两图（§3.1 `arch` / §5.3 `rel`）以 PNG 嵌报告、渲染命令带 `--qa`（几何自检，退出码非 0 先修数据）；arch/rel 无 Mermaid，JSON 存 `分析/` 作复跑源；图标签避免 `★⚠✓` 等特殊字形、不用 `↔`（U+2194 微软雅黑缺字形 → 豆腐块）。
