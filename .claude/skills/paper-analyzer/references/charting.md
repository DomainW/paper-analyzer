> - **§3.1 架构图**（pa_fig `arch` 型）——**论文自己的逻辑架构**：忠实数据流，只画论文本身的信息；

## 总流程（渲染 + QA）

```text
1. 起草 JSON（arch：stages 列流 + nodes + edges；rel：this + 角色 nodes + edges）
2. 渲染 + 内置几何自检（出界/压叠 → 退出码 1 拦下，先修数据再继续）：
   python pa_fig.py <图>.json --png "<分析>/<论文>-架构图.png" --qa
   python pa_fig.py <图>.json --png "<分析>/<论文>-关系图.png"  --qa
3. 报告里嵌入：![<图名>](<论文>-<架构图|关系图>.png)
4. 紧跟该图的「图读法」块（同屏，不许图放 §3 解释在 §6）
5. arch/rel 不出 Mermaid（语义靠图 + 图读法）；JSON 就是唯一可复跑源，存 分析/ 与 PNG 同路径
```

- `--qa` = pa_fig 内置几何自检（仅 arch/rel 生效）：保存前把每个文字窗口换算到画布坐标，文字出 (0,W)×(0,H)（容差 0.02）或两两重叠面积 >0.002 in² → 逐条列出并以退出码非 0 拦下。通过打印「几何 QA 通过」。
- **改动 JSON / 换字体后一律重跑 `--qa`**，QA 过了才允许嵌进报告。

## 两种图型 · JSON schema 与写图纪律

### 3.1 arch —— 论文自身逻辑架构（忠实数据流）

列 = 处理阶段（一列一个阶段名）；框 = 模块/数据（大字短标签 + 小字要点注）；箭头由前一步指下一步。

```json
{
  "type": "arch",
  "title": "PPN 逻辑架构（忠实数据流）",
  "sub": "从左到右 = 处理顺序；小字 = 要点/尺寸/参数/源章节",
  "stages": [
    {"name": "输入", "nodes": [
       {"id": "mix", "label": "混合语音", "note": "48k → 感知特征 68 维", "kind": "input"},
       {"id": "enr", "label": "注册语音", "note": "目标说话人 3s", "kind": "cond"}
    ]},
    {"name": "编码", "nodes": [
       {"id": "enc", "label": "Speaker Encoder", "note": "GRU → 说话人向量", "kind": "module"}
    ]}
  ],
  "edges": [
    {"u": "enr", "v": "enc", "label": ""},
    {"u": "mix", "v": "enc", "label": "逐帧拼接"}
  ]
}
```

**kind → 填色**：`input/cond/feat` 浅蓝（输入/条件/特征）｜`module/decode` 白框主线｜`fuse` 暖黄（融合/查询）｜`output` 浅灰｜`loss` 浅红（虚线箭头）｜`aux` 浅绿。图例自动按实际出现 kind 出。

**写图纪律（arch）**：
- **只放论文自身的信息**：label = 模块名（≤ 一句话，能断行）；note = 模块**要点 + 尺寸/参数 + 源章节**（如 `2×GRU causal · §3.2`），≤ 2 行小字。别放与库内其他论文的横向对比、别放方向级结论。
- **忠实数据流 = 线性推进**：默认每个阶段一列，主干 1 主框从左到右读；并行/分支框放**同一列上下叠放**（上下顺序 = 数据到达顺序）。**避免跨列直连**（A 列直连 C 列会直线穿越中间列框 → QA 会拦出压叠）；确需直连就拆出"直通"中间节点列，或把路径写成相邻列。合并发生在下一列（多条进线指同一框没问题）。
- note 小字 ≤2 行、别把整段证据塞进框；框内长文本会直接压叠。
- 别把"训练策略/评测对比"画进架构图（那不是数据流）；损失框只画"哪几个损失监督哪个输出"。

### 3.2 rel —— 本文与相关论文的关系图（本文中心）

左侧相关论文卡（角色上色）→ 右侧金色本文框；箭头带 [k] 编号，**编号的解释与证据自动生成在图下 k 列表**。

```json
{
  "type": "rel",
  "title": "PPN 与相关论文的关系",
  "this": {"id": "ppn", "label": "Personalized PercepNet (2021)", "note": "本文 · 库内"},
  "nodes": [
    {"id": "percep", "label": "PercepNet (2020)", "type": "pre"},
    {"id": "sb", "label": "time-domain SpeakerBeam", "type": "module"},
    {"id": "nextp", "label": "Dual-Mode (2025)", "type": "next"}
  ],
  "edges": [
    {"u": "percep", "v": "ppn", "evidence": "骨架来源：最小侵入改造（§5 R1）"},
    {"u": "sb", "v": "ppn", "evidence": "TSE 任务定义与 enrollment 条件化先例（§5 R1）"},
    {"u": "nextp", "v": "ppn", "evidence": "后续演进方向（§5 R4）"}
  ]
}
```

**写图纪律（rel）**：
- 以**本文为中心的一跳图**：nodes = 相关论文卡（≤ 6），edges 每条给 `evidence`（短句，带 §5 Rx 出处）→ 图下列表 `[k] 角色 · 论文：证据`。
- 一张图只回答"这篇 vs 相关论文"；**别画成方向综述的家族/演进网**（谁和谁的关系请放到 direction-survey G1/G2）。
- node `type` 用角色色（见下）；本文框金色、放右侧；有向边 `u(相关论文) → v(本文)` 为默认（进入本文），反向箭头（本文 → 后续 R4）由 JSON 里对调 u/v 表达。
- 角色尽量 5 类各 1（R1 前驱/R2 竞品/R3 模块来源/R4 后续/R5 邻域），某角色无 → 按步骤 5 纪律降级说明，不空着也不重复塞同角色。

## 关系边的"词汇表"（rel / lineage 边照用）

前驱·技术来源 ｜ 直接前驱 ｜ 方法同源 ｜ 骨干复用 ｜ 模块借鉴 ｜ 同场竞品 ｜ 同期并列 ｜
启发后续 ｜ 作者团队延续 ｜ 衍生方法 ｜ 邻域参照 ｜ 评测锚点 ｜ 数据集/基准共用 ｜ 引用-被引

> rel 边的 `evidence` 是短证据（关系词 + §5 Rx 出处），长证据留在正文 §5.2 逐篇展开处。

## 图读法（每图必配）

每张图嵌入后**紧跟「图读法」块**（结构固定，内容按图实写）：
1. **这张图回答**：一句话（读者的预期）；
2. **符号**：颜色/箭头/编号一句话；
3. **怎么读（3 步）**：先看什么建立骨架 → 再看什么找细节 → 最后得出什么结论。
最后一句落到"哪些东西图上故意没画、去哪看（方向综述 / 正文哪节）"。

**示例（架构图）**：> 图读法（架构图）——这张图回答"本文方法的数据流怎么一步步走"。从左到右 = 处理阶段，箭头 = 前一步 → 下一步；框内大字 = 模块，小字 = 要点/尺寸/参数/源章节。怎么读：①沿主干从左到右看一遍 → 方法主链路立刻清楚；②看分支框（同一列上下）在哪儿汇入/分出 → 并行结构清楚；③对照每框小字的源章节到正文找细节。图上没画评测/训练对比——那些在 §3.3/§3.4，方向级横向在方向综述。

## 几何红线（无预览时代替肉眼）

本机无 PNG 预览 → **必须程序化几何自检**，不靠肉眼。自检内置在渲染器（pa_fig `--qa`，arch/rel 有效；实现 = 遍历文字窗口→画布坐标，出界/压叠列出并以退出码非 0 拦下）。规则：
1. **箭头走框外**：起点在源框右侧边、终点在目标框左侧边（同一水平带内直连），不穿其他框不压字；arch 跨列直连会被 QA 拦下 → 线性化再画。
2. **文字不出画布、两两不压叠**：交给 `--qa`；改数据后重跑。
3. 字体/字形：脚本自动挑 微软雅黑/黑体/思源；**图内文字不用 emoji**、**不用 `↔` 等 YaHei 缺字（U+2194）**；需要"双向/对照"写"与/对"。
4. 一个数据单位 = 1 英寸；排版按 Measure 量出的尺寸推进，QA 兜底。

## 命名与存放

- 图文件名：`<论文>-架构图.png` 与 `<论文>-关系图.png`，JSON 同名（`<论文>-架构图.json` / `<论文>-关系图.json`）同放 `分析/`。
- 报告中以同目录相对路径 `![…](<论文>-架构图.png)` 嵌入；docx 转换时 pandoc 会带上 PNG。
- 报告 §3.1 紧跟架构图图读法，§5.3 紧跟关系图图读法 + 关系表（`| [k] | 关系 | 从 → 到 | 依据 |`，k 与图一致）。
- 旧版存量（演进树/架构/脉络/关系定位四图 + 对应报告段落）更新前先按「版本留档约定」快照入 `存档/`。
- lineage/scatter2d 仅作为兼容图型保留（pa_fig 仍支持，供旧文件与 examples/脉络图-示例.json 复跑），**新报告不再默认产出**。
