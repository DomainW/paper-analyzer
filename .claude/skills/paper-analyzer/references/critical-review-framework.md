# 批判性分析框架（v3.2）

## 使用指南

本文件是**步骤 4（批判性分析）的总纲与执行规范**，与 `critical-failure-modes.md`（领域必扫清单）配合：

- **`critical-review-framework.md`（本文件）**：讲"怎么审"（CERIC/Nature 两个审问法）+ "审完怎么变成报告五段"（判定表/致命一击/核验/小结的产出规范与口径）。
- **`critical-failure-modes.md`**：讲"审哪些具体病"（语音/ML 失败模式逐项必扫，防漏）。

实际执行 = 先用 CERIC/Nature 建立鸟瞰与对核心主张的质疑 → 用 failure-modes 逐项扫雷保证广度 → 汇入判定表排严重度 → 深挖致命一击 → 标记核验 → 输出小结并回填速览卡。

**原则（不变）**：批判 ≠ 挑刺；每个批判点必须指向原文的具体段落/公式/图表编号，不能泛泛而谈。

## v3.2 批判流程五段

批判不再是"填三张空表"，而是**先广后深、可排级、能挂核验**的五段产出（对应报告 §4.1–4.5）：

| 段 | 产出 | 谁来供料 | 下限 |
|---|---|---|---|
| **4.1 必扫清单结论** | `critical-failure-modes.md` 11 组逐项过：发现/未报告/未发现/不适用 | failure-modes | 无空行；「发现」必须带原文位 |
| **4.2 不足点判定表** | 每条= 类别 · 具体不足(原文位) · 严重度 · 置信度 · 核验 · 改进建议 | 4.1 + CERIC + Nature | **≥8 条**，含 ≥1 条方法/实验硬伤 |
| **4.3 致命一击** | 对最强主张的最强反驳（论证 + 作者辩护 → 为何仍不足/需补实验） | §2.4 最薄弱环节 + CERIC R/I | 必有 1 条 |
| **4.4 可核验性 · 挂资源清单** | 判定表「查不动」项 → 论文根 `资源清单.md` §7 `- [ ]`；「可核验」项注明用哪类资源 | 4.2 的「核验」列 | 逐条归属：可核验/查不动 |
| **4.5 批判小结 · Top-3 缺口** | 按 严重×置信×可修 排 Top3；整体可信度评级；**回填速览卡"最大短板"** | 4.2/4.3 | Top3 + 评级必给 |

> 类别沿用：**声称 / 方法 / 实验 / 论证 / 写作 / 复现**（与 failure-modes 各组的"类别"列一致）。原 v3.1「4.1 方法局限 / 4.2 实验偏差 / 4.3 逻辑跳跃」三张分类表不再并列，统一汇入 4.2 判定表的「类别」列，避免同一条被拆到三处或空表并列。

## CERIC 评估法

来源: Cambridge University Press — *How to Critically Read the Scientific Research Literature*

五维度系统评估。**定位核心主张与最薄弱环节时必用**：

| 维度 | 英文 | 核心问题 | 使用频率 |
|------|------|----------|----------|
| **C** — 主张 | Claims | 论文提出了什么主张？是否清晰明确？ | **每次必用** |
| **E** — 证据 | Evidence | 用什么数据/实验支持这些主张？ | **每次必用** |
| **R** — 推理 | Reasoning | 从证据到主张的推理是否成立？有无逻辑跳跃？ | **每次必用** |
| **I** — 影响 | Implications | 如果主张成立，意味着什么？对领域有何影响？ | 视情况（喂给 4.3/4.5） |
| **C** — 背景 | Context | 在更大的研究格局中处于什么位置？ | 视情况（喂给 4.3/4.5） |

**怎么用出深度**：对论文**最强主张**做一次完整五维拷问（这常是致命一击的原料）；对**最弱环节**（§2.4 已标）做 E→R 追问（这是判定表里"实验/论证"类高严重度项的来源）：

```
最强主张: "我们的方法在 X 上比基线好 Y%"
  ├─ C  主张可证伪吗？范围写清了吗？(X 是哪个集/哪个条件)
  ├─ E  支撑它的是几次运行？误差在哪？(→ failure-modes 组2)
  ├─ R  基线公平吗？Y% 来自同口径复算吗？(→ 组3/组5)
  ├─ I  实际场景里 Y% 有意义吗？代价是什么？(→ 组7)
  └─ C  该基线当时是 SOTA 吗？有更强邻居没比吗？(→ 组3)
```

## Nature 7 步审问法

来源: Nature (2026) — *Seven steps for critically analysing research papers*

系统性鸟瞰到验证。**在写 4.1 前先完整走一遍**建立全局，重点用第 4、6、7 步喂判定表：

### 第一阶段：鸟瞰 (Aerial View)
- **步骤 1 扫描摘要和图表**：先不读正文，只看 Abstract + 图/表——能仅凭它们读懂主要发现吗？（写作类不足常在此暴露）
- **步骤 2 识别核心研究问题**：要回答什么问题？值得吗？（喂 4.2「声称」类）
- **步骤 3 定位知识空白**：声称填补的空白真实吗？还是"制造"的？相关工作覆盖够吗？（喂 4.2「论证」类）

### 第二阶段：审问 (Interrogation)
- **步骤 4 评估方法**：方法适合问题吗？数据规模/质量/偏差够吗？消融覆盖所有关键组件吗？超参细到可复现吗？代码数据开源吗？——**这一步直接映射 failure-modes 组 4/6/8**。
- **步骤 5 形成自己的结论**：在读 Discussion 前，基于已见实验先下你自己的结论，再读作者 Discussion 对照差异——差异点常是"过度声称/回避局限"的直接证据。

### 第三阶段：验证 (Verification)
- **步骤 6 交叉检查解读**：结论被数据充分支持吗？有无其他解释？结果是否"过于完美"？（→ 组2 seed/误差棒、组10 oracle/泄漏）
- **步骤 7 更广泛的意义**：真实贡献？5 年后还重要吗？为谁开大门？（喂 4.5 的评级与 4.3 的背景）

## 不足点判定：严重度 / 置信度 / 核验 口径

### 严重度（影响报告可信度/结论成立的程度）
| 级别 | 含义 | 例 |
|---|---|---|
| 🔴 **致命** | 击中核心主张，结论可能被推翻或不可信 | 代码实际非因果却称因果；测试说话人与训练重叠；声称 vs 表数值打架 |
| 🟠 **重要** | 削弱一般性/量化说服力/公平性，通常需补实验 | 无多 seed/显著性；基线非当时 SOTA；只报最好结果 |
| 🟡 **一般** | 影响完整度/观感/复现便利，rebuttal 可补 | 超参细节缺失；图不清晰；引用自增强 |

### 置信度（你对该不足判断有多确定）
| 级别 | 含义 |
|---|---|
| 高 | 有原文页码/表号直接对证，几乎无歧义（如正文 vs 表数值冲突） |
| 中 | 从原文可推断成立，但依赖一定解读（如"按 16k 数据该用 Wb-PESQ 但未声明"） |
| 低 | 是合理怀疑，需拿到代码/数据/额外信息才能证实（如实写"待核"） |

### 核验（这条不足能否被复现侧实证）
| 值 | 含义 | 挂资源清单 |
|---|---|---|
| 可核验·类N | 官方代码/数据/评测脚本/环境可得，可按第 N 类资源实证 | 交 paper-reproducer 步骤复算 |
| 查不动·无代码 | 官方实现未开源（清单类2 ⛔）→ 无法查内部实现 | §7 `- [ ]` 待作者释出后核 |
| 查不动·无数据 | 数据受限/未开源（类3 ⛔）→ 无法查跨集/泄漏 | §7 `- [ ]` 数据到位后核 |
| 查不动·需环境 | 需 GPU/特定版本才能复算统计量（类6） | §7 `- [ ]` 环境就绪后核 |
| —（纯文本） | 仅靠重读原文即可判（声称幅度、内部不一致） | 不挂 |

> §4.4 只把「查不动」且**影响判定**的项登记进 `资源清单.md` §7；纯写作/观感类不进清单。

## 致命一击怎么写

对论文**最强（最想让读者信）的主张**给出最强反驳。不是罗列，是**一段式论证**：

1. **靶子**：一句话点名最强主张（如"复数域三通道+相位优化带来低 SNR 提升"）。
2. **致命角度**：选最能动摇它的一个角度——反例、混淆变量、口径偏差、无对照、测量污染（从判定表最高严重度项里挑，别另起新话）。
3. **作者可能的辩护**：预演作者会怎么答。
4. **为何仍不足 / 需要什么**：指出辩护没堵上的洞，或给出能一锤定音的最小实验（通常 1 个，最好"拿官方代码就能跑"）。
5. **如可复算**：把验证路径写进 §4.4 挂清单（同一条进 4.3 与 4.4）。

写法纪律：2–4 句紧凑论证即可，**不要铺开成小论文**；引用原文位；语气是"审稿人会这样问"，不是"我断定这是造假"。

## 批判性分析写作要点

### 原则
1. **批判 ≠ 批评**：客观评估边界与前提，而不是挑错。
2. **证据驱动**：每个批判观点都要有原文依据或推理逻辑。
3. **建设性**：指出问题后，给出最小可行动作（不是空泛"应加强验证"）。
4. **不过度解读**：不要把自己的假设当作论文的问题——拿不准标置信度"低·待核"。
5. **注意语气**：谨慎客观，"可能受限于…""值得进一步验证…"。
6. **具体化**：每条都带原文页码/公式/表格号。"实验设计有偏差"不如"Table 4.10 仅英文低 SNR + 中文零样本，未见大词汇量/带噪远场/真实场景检验"。

### 一句话 vs 一段：多少算够
- **4.2 判定表每条**：一句话描述（含原文位）即可，把论证留给 4.3 与小结。
- **4.3 致命一击**：一段式论证（见上）。
- **4.5 小结**：Top3 各一句话+整体评级一句。
- 全文加起来通常 600–1000 字可控，**不追求长**，追求每条扎得准。

### 推荐表达
| 目的 | 表达 |
|------|------|
| 指出局限 | "该方法假设…，当…时可能不成立" |
| 指出不足 | "消融未覆盖 X 组件，其对整体性能的贡献尚不明确（Table 4.9 A→E 缺…）" |
| 指出偏差 | "训练数据主要来自…，在…场景下的泛化能力有待验证" |
| 提出疑问 | "作者声称 X 优于 Y，但仅比较了…条件，…条件下表现未知" |
| 建设性建议 | "若能补 X 实验/证明…，结论将更有说服力；该实验以官方代码即可复算（§4.4）" |
