## 1. 检索顺序（每篇论文固定走一遍）

| 步 | 干什么 | 怎么干 | 命中标准 |
|----|--------|--------|---------|
| 1 | **从论文自身找** | 看 footer / acknowledgment / "Code available at" / 参考文献里作者自引的 GitHub 链接；通讯作者主页；致谢 | 链接直接含模型名或 DOI |
| 2 | **官方代码（GitHub）** | `pa_query.py github "<模型名> speech enhancement"`，多组关键词；再看论文同名 repo 的 stars/作者/License | repo 作者含论文作者、描述含论文标题或 "official implementation" |
| 3 | **HF 数据集/权重** | `https://huggingface.co/api/datasets?search=<数据集词>` 等 | 数据集卡作者/论文链接吻合 |
| 4 | **社区复现** | GitHub 再搜 `"<模型名>" pytorch`、`<模型名>-pytorch`、fork 数高的 | 明确自称复现该论文（读 README 确认方法对齐） |
| 5 | **更新到资源清单** | 逐项填表；找不到的写"未找到"并留待查词 | — |

**时间盒**：本步 15–20 分钟内完成，不要无限追链；未确认项进 §5「待查」。

## 2. 判断"官方 vs 第三方"的铁律

一个仓库要标 **官方**，需同时满足尽量多：
- 作者/组织含论文作者（比对论文作者列表，而非只看 repo 名）；
- README 或描述声明 "official implementation of <论文标题>";
- 引用论文 DOI/arXiv 链接；
- stars/License/代码语言与论文一致。

**存疑一律标"疑似第三方，待确认"**，别把社区复现当官方写入报告引证。

## 3. 下载与落位（Windows 注意）

```bash
# 官方代码镜像 → 资料/（小仓库浅克隆；大仓库只记录链接+说明）
cd "<论文文件夹>/资料"
git clone --depth 1 <官方repo-url> official-<repo名>     # 成功则删 .git 减重？不——保留以便更新
# 若只想留个"指针"而非整仓：把 README/LICENSE 复制成 official-<repo名>-说明.md 即可

# 数据下载脚本 → 数据/下载脚本/<数据集名>.sh（或 .py），可重复执行
mkdir -p "数据/下载脚本"
```
> 路径含中文/全角括号时**一律用引号**；`cd` 用完整路径避免权限弹窗。

## 4. 许可三条线（必须分别记录）

| 许可对象 | 含义 | 典型值 |
|---------|------|--------|
| 代码 | 能否复用/商用 | MIT / Apache-2.0 / BSD / **无 → 慎用** |
| 数据 | 能否分发/再训练 | CC0 / CC-BY / 研究用途限制（如 DNS 挑战、VB 需申请） |
| 模型权重 | 能否商用（尤其语音） | 常见"非商用"条款，复现时留意 |

**数据落位原则**：只把**允许再分发的公开数据**真正下进 `数据/`；受限数据只记官方下载入口与许可，不放本地。

## 5. 资源清单必填项（宁缺毋滥但别留空洞）

- 代码：地址、是否官方、语言、许可、是否镜像到 `资料/`；
- 数据：用途、规模、地址、许可、下载脚本路径、本地状态（未下/部分/完整）；
- 配套：评测脚本、补充材料、模型权重链接；
- 复现对齐：官方数值 = 原文哪张表（如"对齐 Table 3"），供 `复现/README.md` 引用；
- 待查：没找到的东西 + 下一步检索词。
