# 🚀 v2.1.2（2026-09-19）— 缺口解析修复：正文里的 `- [ ]` 字面量不再被误当待办

## 症状

`复现进度图.png` 底部「缺什么」红条里出现**半句乱码**（形如 `项 → 资料·<类> 缺口」顺序取用，超出的条目不会上图…`），并且**挤掉一条真缺口**——面板只留 8 条。

## 根因（`scripts/pr_status.py` · `parse_readme()`）

未勾项解析用的是**整行子串匹配**，取值又切在**第一个** `]` 之后：

```python
for ln in lines:
    if "- [ ]" in ln:                     # ← 行内出现该字面量就算，不要求出现在行首
        t = ln.split("]", 1)[1]           # ← 从第一个 "]" 之后切 → 正文场景切在半句中间
```

于是 README **正文**里提到的字面量 `- [ ]` 被当成真待办。最典型的种引信者是
`templates/复现README-模板.md` 的提示句「…或 §8/§9 的 \`- [ ]\` 待办，会随图呈现」——
**它被逐字拷进每一份新建 README**。

缺口面板合成顺序为 `README 未勾项 → 步骤 ⛔ 受阻 → 清单缺口`，去重后 `gaps[:8]` 截断：
幽灵项排在真缺口**前面**，故真缺口被挤掉、乱码句被画进 PNG。

## 修复

1. **`scripts/pr_status.py`**：`parse_readme()` 改**行首锚定**
   `re.match(r"^\s*[-*]\s*\[ \]", ln)`，取值同步改 `re.sub(r"^\s*[-*]\s*\[ \]\s*", "", ln)` 剥前缀。
   口径与同文件 `parse_manifest_notes()` 的 `s.startswith("- [ ]")` 拉齐——后者本就安全，
   故 `资源清单.md` §7 标题里的同类字面量从来不受影响。
2. **`templates/复现README-模板.md`**：提示句改写为「§8/§9 的**未勾选清单项**（行首复选框 `- [ ]`）」，
   不再把字面量种进正文。
3. **`references/visualization-guide.md`**：缺口来源第 1 条补「**只认行首** `^\s*[-*]\s*\[ \]`」口径；
   §8 常见坑新增一行「缺口里出现半句乱码」。

## 影响面

- 库内 **7 份** `复现/README.md` 经只读复核**当前 0 条幽灵**（此前已改写措辞），故**无需重出任何进度图**；
  本修复防的是**此后新建**的 README（模板即引信源）。
- 不改图型、不改 JSON 结构、不改 `资源清单.md` 解析。

## 快照

修复前整份 skill：`存档/skills-前版本/paper-reproducer-v2.1.1-2026-09-19-缺口解析前/`。
