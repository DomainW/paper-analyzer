# 论文复现（Paper Reproducer）

**目标**：对库内某篇论文，走完「环境 → 数据 → 代码 → 冒烟 → 指标对齐」闭环。
**完成线**：在**同口径**下把论文指定表（如 VB PESQ 3.58）对齐；对不上 → 产出差异分析，不硬凑。
> 版本：**v2.1.3**（2026-09-19，路径同步 `已分析/<发表年>/`）；变更见 `CHANGELOG.md`。v2.1.1 起版本戳进入 `存档/skills-前版本/`，v1/v2 见 `存档/skills-前版本/paper-reproducer/`。
> **v2.1.3（2026-09-19，路径同步 · 无脚本改动）**：配合 paper-analyzer **v4.1.0** 把归档出口改为 `已分析/<发表年>/<论文名>/`，本文「关键约定」与步骤 1 的候选路径改带发表年层（**两种布局都认**：候选扫描按 `已分析/**/资源清单.md` 递归，新布局与旧扁平布局同时命中）、`references/visualization-guide.md` 命令示例路径同步。**`scripts/` 与模板零改动**（`pr_status.py` 等本就按**传入的 README 路径**工作，仓库内已核无 `已分析/` 硬编码）。
> **v2.1.2（2026-09-19）**：`pr_status.py` 的未勾项解析由**整行子串** `"- [ ]" in ln` 改为**行首锚定** `^\s*[-*]\s*\[ \]`（取值同步改 `re.sub` 剥前缀）——正文里出现 `- [ ]` 字面量（模板提示句即一例，会被逐字拷进每份新 README）不再被当成真待办、不再切出半句乱码挤掉 `[:8]` 里的真缺口；模板提示句同步改写，`visualization-guide.md` 补「行首匹配」口径与常见坑一行。

## 关键约定（与 paper-analyzer 的论文库联动）

- 一篇论文 = `论文库/<学科>/<方向>/已分析/<发表年>/<论文名>/`（**v2.1.3 起**：`已分析/` 下先按论文发表年分目录，配合 paper-analyzer v4.1.0；旧的扁平布局 `已分析/<论文名>/` 仍认），内含：
  `原文/`(PDF+文本) `分析/`(报告+图) `复现/`(我们跑的代码) `数据/`(数据集，下载脚本在 `数据/下载脚本/`) `资料/`(官方代码镜像/权重配置/评测脚本/补充，按类分子目录) + **`资源清单.md`**(复现资料六类分类收集清单)。
- **`资源清单.md` = 复现的"资料收集操作源"**：分析（paper-analyzer 步骤 6）建初稿，复现从 **状态 `☐/⛔`** 的资料行开始照单收集；每收一项把该行状态改 `🔄→✅`。类目对应：类 2 代码 → 步骤 5，类 3 数据集 → 步骤 4，类 5 评测 → 步骤 7，类 6 环境 → 步骤 3。收集方法查 `paper-analyzer/references/collection-guide.md`。
  > **paper-analyzer v4.1.0 起，步骤 6 默认跳过**（该 skill 默认只出 md 报告 + 两图，省 token）——库内**新**论文很可能**没有** `资源清单.md`。此时两条路：① 请用户先跑 paper-analyzer **A+ 模式**补建该清单（推荐，六类初稿与人手核过的来源更齐）；② 直接开工，**由本 skill 在步骤 3 建一份**（复制 `paper-analyzer/templates/资源清单-template.md` 到论文根，边收边填，语义同）。**别把"清单不存在"当成"无资料可收"**。
- 复现消费 `资源清单.md` 与分析报告 §3.4/附录（目标表、超参、官方数值），复现中发现的新链接/勘误/版本差异**回写** `资源清单.md` 并刷新其 §0 收集进度总览。
- 复现全程只写 `复现/` 与（数据）`数据/`；不擅动 `原文/ 分析/`。

## 进度可视化（一张图看懂"走到哪、缺什么"）

复现进度有**两张图**，都由 `scripts/pr_status.py` 生成：**PNG**（可直接嵌 md/docx）+ **Mermaid**（可编辑源，双轨同内容）。

1. **通用流程总览**（教"复现怎么一步步走"）→ `assets/复现流程总览.png`：8 步闭环 + 步骤 7 完成线判定 + 「否 → 差异分析(三查) → 修正回炉」回环。仅当流程本身改动时重生成。
2. **单篇进度图**（"这篇论文复现走到哪一步、缺什么"）→ `<论文>/复现/复现进度图.png`：读 `复现/README.md` 的**复现进度状态块**表格（模板 §0），把 8 步三态画成卡片，并在图下/控制台**自动打印「缺什么 / 下一步」**。

**缺口自动推导**的来源（想补更多 → 人工写进 README 的 `- [ ]` 或 ⛔ 说明里，或把 `资源清单.md` 对应资料行标 `☐/⛔`，会随图一起呈现）：
- README 里仍未勾选 ✅ 的 `- [ ]` 任务（含各节清单）；
- 状态块中 ⛔ 步骤（其受阻原因）；
- 可选：论文根 `资源清单.md` 中 `- [ ]` 待办（脚本自动到上级目录找）；
- `资源清单.md` 六类清单表中**状态为 `☐` / `⛔` 的资料行**（前缀 `资料·<类>`，v2.1 起，把"资料没收集齐"也画进缺口）。

生成 / 更新命令（**步骤 2 建骨架后**与**步骤 8 收尾时**各跑一次单篇命令；Windows 记得 `PYTHONIOENCODING=utf-8`）：
```bash
# 单篇进度（在 README 同目录生成 复现进度图.png/.mermaid 并打印缺口）
python .claude/skills/paper-reproducer/scripts/pr_status.py "<论文>/复现/README.md"
# 通用总览（仅改流程时）
python .claude/skills/paper-reproducer/scripts/pr_status.py --overview -o .claude/skills/paper-reproducer/assets/复现流程总览.png
```

> 细则见 `references/visualization-guide.md`：状态块列头必须原样、状态取值、缺口推导规则、Mermaid 手工编辑如何回灌。

## 工作流（TaskCreate 建 8 步跟踪；状态三态：✅完成 / 🔄进行中 / ⛔受阻+原因）

```
进度：
- [ ] 步骤 1: 选论文 + 定义复现目标
- [ ] 步骤 2: 建 复现/README.md 骨架（勾选清单）
- [ ] 步骤 3: 环境就绪（版本记录）
- [ ] 步骤 4: 数据就绪（落位 + 许可/口径记录）
- [ ] 步骤 5: 代码就绪（官方优先，否则手搓）
- [ ] 步骤 6: 小规模冒烟（先跑通再放大）
- [ ] 步骤 7: 指标对齐（目标表同口径 + 差异分析）
- [ ] 步骤 8: 收尾（更新状态、登记卡点、回写清单、汇报）
```

## 步骤 1：选论文 + 定义复现目标

1. 候选 = `论文库/**/已分析/<发表年>/<论文名>/`（递归扫 `已分析/**/资源清单.md` 即可，两种布局都能命中；有 `资源清单.md` 者优先）。用户未指明 → 列出候选，AskUserQuestion 选择。
   - 若论文**尚未分析**（如 `未分析/` 下只有训练代码待配论文）：先提示可先用 paper-analyzer 分析；或本 skill 直接基于原文/代码做目标定义。
2. **锁定目标表与口径**（复现的"锚"）：
   - 论文里最关键 1 张结果表（如 VB PESQ/STOI/CSIG…）+ 1 组关键对比；
   - 评测协议：数据集划分、SNR 设置、指标包与版本（PESQ 宽/窄带、STOI 是否 extended）、增强前基线数值；
   - 来源：`分析/报告` 附录 + 原文页。把两者不一致处记作**版本注**。
3. 记录硬件/时长预期（本机常见 2×RTX4090；单卡/多卡、训练量级估算）。

**产物**：`复现/README.md` 开头写清「复现目标 = 对齐 Table X 的 PESQ Y、STOI Z（±Δ），官方数值出处」。

## 步骤 2：建 `复现/README.md` 骨架

1. 复制 `templates/复现README-模板.md` → `<论文名>/复现/README.md`，填入目标表/口径/完成线；H1「——」后写简短别名（供进度图标题）。
2. 之后每步更新模板 §0 **复现进度状态块** + 各节清单；README 即该论文复现的**唯一状态记录**。
3. 核对论文根 `资源清单.md` 六类：把 `☐/⛔` 的资料行排成"收集待办"（哪些是步骤 3/4/5/7 各自要收的）。
4. 骨架填完即跑一次 `pr_status.py <该README>` 生成初版 `复现/复现进度图.png`（此时图底应已含 资料· 类缺口），并把打印的缺口清单排入计划。

## 步骤 3：环境就绪

1. 读 `资源清单.md` 类 6「环境与依赖锁定」+ 论文要求（框架/依赖/版本/硬约束如"需 Linux+CUDA"）。
2. 建独立 venv 或 conda 环境并命名（如 `.venv-repro-<论文缩写>`），README 记录：Python/CUDA/框架/关键包版本、GPU。
3. 依赖装齐后用 `--version`/`import` 快速自检，README 打 ✅，并把 类 6 对应行状态更新 `🔄→✅`、`pip freeze` 留档。

## 步骤 4：数据就绪

1. 按 `资源清单.md` 类 3「数据集与 manifest」逐行收集：公开可分发数据 → 下载到 `数据/<数据集>/`，下载脚本留存 `数据/下载脚本/`；
   **受限数据（VB/LDC 等需申请）** → 提示用户手动下载后放入，README 记入口与许可，不代下载；等开源 → 登记追踪。
2. 每条数据落位后把清单对应行状态 `🔄→✅`（受限数据放好后同样标 ✅ 并注明"用户放入"）。
3. 记录：**训练/验证/测试划分口径、采样率、SNR 合成参数**是否与论文一致（这是指标对齐的第一大坑）。
4. 小数据试跑确认路径/加载无误；manifest 为绝对路径的用论文脚本重建。

## 步骤 5：代码就绪（官方优先，否则手搓）

**有官方代码**（`资料/official-代码/` 或 GitHub，先查 `资源清单.md` 类 2）：
1. 代码放 `复现/src/`（从 `资料/official-代码/` 复制或浅 clone）；
2. 核对分支/commit、与论文是否同一版本（预印本 vs 正式版 → 版本注）；
3. 修通跑向（README 记每条改动）；
4. 把类 2 对应行状态 `🔄→✅`（镜像已定位的确认路径）。

**无官方代码 → 手搓路径**：按 `references/implementation-guide.md` 走（读报告拆组件 → 按论文规格实现 → 先结构自检）。
> 决策问用户确认一次：「走官方代码还是手搓实现？」（涉及工作量，默认先查官方）。

## 步骤 6：小规模冒烟

- 先 1 个 batch / ≤2 epoch / 1 条样本推理，确认 前向→损失→反向→存盘 全通；
- 用**极小数据**跑一轮完整训练拿到"能下降"的损失曲线证据，再放大；
- 冒烟问题就地修，README 记录。

## 步骤 7：指标对齐（完成线判定）

1. 在步骤 1 锁定的**同口径**下复测指标（评测脚本尽量复用官方 evaluate；无官方用指标包实现并记版本）。
2. 填对齐表：

| 指标 | 论文数值 | 复现数值 | Δ | 判定(✅/⛔) | 备注 |
|------|---------|---------|----|-----------|------|

3. 判定默认容忍：PESQ ±0.05；STOI ±0.01；SI-SDR/SNR ±0.5 dB；精度类 ±1%（具体指标在步骤 1 预设，可改）。
4. 超容忍 → **差异分析（三查）**（见 implementation-guide）：
   ① 版本/口径（损失权重、网络超参、预印本 vs 正式版）
   ② 实现细节（模块、初始化、padding/causal、学习率策略）
   ③ 评测协议（数据划分/SNR/指标包/种子）
   → 记录结论：可解释归因 / 待排查项。
5. **达成完成线**才把 README 标记 ✅；未达成保持 🔄/⛔ 并如实汇报。

## 步骤 8：收尾

1. README 填结论：是否对齐、偏差归因、遗留问题清单（⛔ 项写明求助点）。
2. **回写** `资源清单.md`：找到的官方链接、下载的数据与许可、复现对齐目标（如"对齐 Table 3"）；把收集清单各涉及行更新至最终状态 ✅/⛔，并刷新 §0 收集进度总览。
3. 更新 §0 **复现进度状态块**至最终三态，重跑 `pr_status.py <该README>` 刷新 `复现进度图.png`（保证内嵌图与 README/资源清单 一致——此时 资料· 类缺口应已消或只剩 ⛔）。
4. 如需，向用户汇报：状态(✅/🔄/⛔)、对齐表、卡点、下一步建议（可附进度图）。

## 手把「论文复现不成功」的排查顺序（Quick Debug Ladder）

```
报错/结果差？
├─ 先确认：数据划分/SNR/采样率与论文一致？        ← 第一大坑
├─ 指标包版本一致？（PESQ 宽窄带、pystoi 版本、DNSMOS 需联网）
├─ 再确认：网络超参/损失权重/学习率策略与论文一致？
├─ 训练充分？（epoch、batch、是否收敛曲线仍在降）
├─ 再查实现细节（模块等价、causal/padding、初始化、混合精度）
└─ 仍不行 → 记录 ⛔ 并汇报：最小复现 + 日志 + 已排除项
```

## 反模式（别做）

- ❌ 指标对不上就调参"凑数"——必须差异分析归因；
- ❌ 直接往 `原文/分析/` 塞代码或改分析产物；
- ❌ 下载受限数据或忽略许可（只下允许再分发的公开数据）；
- ❌ 训练无日志/无 README 状态裸跑——每步三态留痕；
- ❌ 复现半途放弃却不留 ⛔ 说明——卡点本身是资产。
