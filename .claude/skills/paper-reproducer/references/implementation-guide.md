## 1. 手搓实现流程

前提：`资源清单.md` 无官方代码（已按 paper-reproducer 步骤 5 问过用户确认走手搓）。

1. **拆组件**：从 `分析/报告 §3.1`（架构图/逐模块）+ 原文正文，列出必须实现的模块清单：
   前端（STFT 参数、窗、hop）、编码/解码、核心块（含每块内卷积/注意力/SSM 的子结构）、融合/skip 方式、双解码头或掩码方式、损失项与权重。
2. **逐组件对齐原文规格**：用原文公式编号标注每个模块的出处（Eq.X / Section Y）；超参用论文"实验设置"而非猜。
3. **按"可冒烟"最小骨架搭起**：先写数据加载 + 一个完整前向（固定 batch），形状断言通过后再补损失与训练循环。
4. **损失权重核对**：复合损失逐项实现并用小样例验证量级（防某单项主导）。
5. **训练循环**：optimizer/scheduler/epoch/混合精度 与论文一致；不同则记版本注。
6. **先复现"论文用的基线"更稳**：若手搓目标模型成本高，先用论文对照的公开模型（如库内 SEMamba/Conv-TasNet 代码）跑通评测管线，再做目标模型——把「评测管线」与「模型」两个变量分开验证。

## 2. 结构自检

- [ ] 输入/输出形状在关键跳变处有断言（编码后、core 后、解码拼接处）；
- [ ] causal vs non-causal：padding / 是否使用未来帧，与论文"实时/因果"声明一致；
- [ ] 频率维度对齐：STFT 点数、帧移、mask 与相位合成方式与论文一致（510/120 与 512/256 这类差异是高频坑）；
- [ ] 幂压缩系数、窗类型（Hamming/Hann）与论文一致；
- [ ] 复数/双路径分支等"论文自造模块"逐行对照公式实现。

## 3. 指标对齐「三查」

结果对不上论文数值时，按顺序排查，**每查到一条就记录，禁止直接调参凑数**。

| 查 | 细项 | 示例问题 |
|----|------|---------|
| ① 版本/口径 | 论文版本差异 | 预印本 vs 正式版 vs 学位论文第几章（数值、损失权重、STFT 全不同）|
| | 训练超参口径 | epoch/batch/lr 策略/损失权重/输入特征（幅值幂压缩系数）|
| | 是否用了论文声称的"额外技巧"（如 PCS 重打分、多目标） | |
| ② 实现细节 | 模块等价性 | 注意力头数、扩张率、归一化位置、激活 |
| | 初始化 / 预训练权重 | 是否随机初始化即可复现论文基线 |
| | 数据预处理细节 | 混音方式（同噪声文件不同 SNR 段）、是否静音裁剪、说话人集合 |
| ③ 评测协议 | 数据划分 | 训练/测试集合、句子数、噪声集合、SNR 范围（重点：测试集随机种子）|
| | 指标包版本 | PESQ 宽/窄带与脚本、pystoi 版本、SI-SDR 是否含 DC/缩放、DNSMOS 需联网与版本 |
| | 增强前"基线值" | 论文 Noisy 列是否=你的带噪输入（口径先对齐再看 Δ）|

> 记录格式：`发现：xxx → 修正：xxx → 数值变化：a→b`。全部三查后仍不达标 → README 置 ⛔ 并附最小复现。

## 4. 指标包与版本坑

- **PESQ**：宽带 PESQ（16k）与窄带（8k）数值体系不同；用 `pesq` 包时注意 `-1`（wb）/`0`（nb）；带噪输入也有 PESQ 基线，别只报增强后。
- **STOI / extended STOI**：`pystoi` 版本与 `estoi=True` 会改数值；采样率与帧参数要按论文。
- **SI-SDR / SDR**：是否有尺度不变归一；`sdr`（bss_eval）口径更严，别混。
- **Δ 指标**（低 SNR 场景）：论文若报"ΔSNR/ΔSTOI（相对带噪输入）"，复现必须用同一输入基线算差。
- **生成指标**（如 DNSMOS）：需联网/模型权重，版本与论文一致，且不能离线替代。

> 原则：评测脚本能复用官方 evaluate.py 最好；自己实现则把**每条指标的命令/版本**写进 复现/README，使"复现我的复现"成为可能。

## 5. 训练排障速查

```
损失 NaN/Inf        → 检查 lr、混合精度、输入是否含 NaN、log(0) 防护
损失不降            → 先极小数据过拟合测试(应能降到很低) → 修模型 → 再放大
收敛但指标上不去    → 回到 §3 三查（最常见是数据划分/SNR/评测口径）
OOM                → 降 batch/分辨率；fp16；梯度累积
显存/速度瓶颈      → 报告 RTF/时长，若与论文声明差距大→查实现是否多算
Windows 特有        → 路径中文/全角符号一律引号；dataloader num_workers=0 或 spawn 注意
```

## 6. 长训练 / 续训

- 训练即落**checkpoint + resume**（含 optimizer/scheduler/step）；每 N epoch 存一次；
- 日志：loss/val 曲线、每 epoch 时长；**总时长估算**在步骤 1 就写入 README，超预期先报备；
- 论文声称硬件（如 2×RTX4090、200 epoch）不可得时：改小数据量/缩短轮次做"趋势验证"，并在 README 写明这是近似而非完成线。
