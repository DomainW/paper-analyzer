## 1. 两张图与产物

| 图 | 输出 | 内容 | 何时生成 |
|----|------|------|---------|
| 通用流程总览（教学） | `assets/复现流程总览.png` + `.mermaid` | 8 步闭环 + 完成线判定 + 差异分析回环 | 流程改动时（一般仓库维护） |
| 单篇进度图 | `<论文>/复现/复现进度图.png` + `.mermaid` | 8 步三态卡片 + 底部「缺什么/下一步」 | 步骤 2 初建、步骤 8 收尾，以及状态块每次大改后 |

两条产物**同源**：PNG 供人看/嵌文档；Mermaid 是可编辑源（GitHub/typora/mermaid.live 可渲染、可改），手工改了 `.mermaid` 不会回写 PNG。

脚本三态映射（与 README 同一套约定）：`✅` 完成（绿）、`🔄` 进行中（金）、`⛔` 受阻（红）、其余/`—` 未判定（灰蓝）。

## 2. 复现进度状态块规格

脚本在 `复现/README.md` 里找一个**表头含「步骤｜状态｜说明」三词**的表格（模板 §0），逐行读取，**行首数字 = 步骤号**：

```markdown
| 步骤 | 状态 | 说明 |
|------|------|------|
| 1 选论文·定义目标 | ✅ | 目标表/完成线见 §1 |
| 3 环境就绪 | ⛔ | 无 GPU/Windows：mamba_ssm 需 Linux+CUDA，待选 A/B/C 路径 |
```

约束（脚本按此解析，**别改格式**）：
- 每行以 `|` 开头，第 1 格 = `步骤号 + 名称`（以数字打头即可）；
- 第 2 格状态取值限 `✅ / 🔄 / ⛔ / —`（或留空）；`—`/留空 = 未判定；
- 第 3 格一句话说明（会显示在卡片副行，超宽自动截断；受阻 ⛔ 的原因建议写这里，会被列入「缺什么」）；
- 步骤名写不写序号皆可（模板已给 1–8），多出来但没在 8 步里的行会被跳过；
- 表格若不在文件开头也没关系，脚本会扫描整份 README；但整份文件**只放一张**这样的状态块。

## 3. 「缺什么 / 下一步」如何推导

图底部与脚本控制台输出的缺口 = **四类来源去重**：
1. 全文仍未勾选 ✅ 的 `- [ ]` 任务行（步骤清单、各节待办都算；**只认行首** `^\s*[-*]\s*\[ \]`，v2.1.2 起）；
2. 状态块里 `⛔` 的步骤及其受阻说明（无说明则提示"原因未写明"）；
3. 论文根 `资源清单.md` 的 `- [ ]` 待办（默认取 `<论文>/资源清单.md`，脚本自动到 README 上级目录找；`--manifest` 可改）；
4. `资源清单.md` **六类清单表中收集状态为 `☐` / `⛔` 的资料行**（v3.1 起）：即"代码/数据/权重/评测/环境还没收齐"也画进缺口，前缀 `资料·<类>`（如 `资料·数据集与 manifest： VB（需用户放入）`）。

**人工补充**：脚本只列"能从文档机械推出的"缺口。像"等用户手动下载受限数据""等作者开源数据链接"这类人肉事实，写在对应步骤的说明里，或作为 `- [ ]` 待办写在 §8 卡点 / §9 下一步、或把 `资源清单.md` 对应行状态标成 `☐/⛔` 并在格内补一句——下回跑脚本就自动带上图。
完全没缺口时，图底显示提示行，请人工补备注，别让"看似无缺口"掩盖真实待办。

## 4. 命令速查与 Windows 注意

```bash
# 单篇进度（在 README 同目录生成 复现进度图.png/.mermaid，并打印缺口）
python .claude/skills/paper-reproducer/scripts/pr_status.py \
  "论文库/<学科>/<方向>/已分析/<发表年>/<论文名>/复现/README.md"

# 指定输出名 / 换资源清单路径
python .../pr_status.py <README> --out <自定义图.png> --manifest <资源清单.md>

# 通用总览（写入 skill 的 assets/）
python .../pr_status.py --overview -o .claude/skills/paper-reproducer/assets/复现流程总览.png
```

Windows 提示：
- 中文/全角路径一律**加引号**；Git Bash 传 `C:/...` 给 python 没问题；
- 控制台乱码/编码错 → 前缀 `PYTHONIOENCODING=utf-8`（或 `-X utf8`）；
- `.mermaid` 与 PNG 同前缀，`--mmd` 可指定。

## 5. 嵌入到 README / Word

README（相对本目录，模板已给）：


转 Word 时 PNG 原样嵌入即可（图宽约 13.5 英寸，若过宽可在 md 里用 `<img width="900">` 或转 Word 后缩放到页宽）。

## 6. 想手工改图

- 只想加标注/改色 → 直接编辑 `.mermaid`（改完在 GitHub/typora/mermaid.live 里看），不要手工改 PNG；
- 想改"下一步流程"（改总览）→ 编辑脚本里 `STEP_META` / `render_overview_png` 文案后重跑 `--overview`；
- 想让某篇 README 的进度图反映最新状态 → 更新 §0 状态块 + 各节 `- [ ]`，**重跑单篇命令**（不要手改 PNG）。

## 7. 无 matplotlib 环境

脚本会先写 Mermaid、PNG 画不出来时打印 `[PNG 失败] …` 仍正常结束：
- 有 Mermaid 就够在支持 Mermaid 的阅读器看；要 PNG 才装 `pip install matplotlib`。
- 中文字体：Windows 自动用微软雅黑/黑体；mac/Linux 需存在 Noto/PingFang 等 CJK 字体，否则标题/中文说明会缺字（脚本打印缺字形警告而非崩溃）。

## 8. 常见坑

| 现象 | 原因 / 修法 |
|------|------------|
| 图里步骤全是"未判定/待办" | README 没有 §0 那样的状态块（或列头被改），对照模板重建 |
| 缺口列不出某条待办 | 那条不是**行首** `- [ ]` 格式；或写在 `- [x]`（已完成）里 |
| 缺口里出现半句乱码 | README **正文**（非行首）里写了 `- [ ]` 字面量——v2.1.2 起只认行首复选框；把正文里的该字面量改写（如「未勾选清单项」），别让它进正文 |
| 资料缺口没出现 | 资源清单那行状态不是 `☐`/`⛔`（🔄/✅ 不算缺口）；或状态写在非"状态"列；资源清单不在 `<论文>/资源清单.md`（用 `--manifest` 指） |
| 某步状态没更新 | 状态块与正文各节是两套，脚本只认 §0 状态块，别只改正文 |
| 标题/文字变方块 □ | 缺 CJK 字体（见 §7）；或文本含 ✅🔄⛔ 等 emoji（图中记号由内置字体画，**不要把 emoji 写进步骤说明/标题**）|
