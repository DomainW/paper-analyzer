# paper — Claude Code 论文工作流 Skills

**中文** ｜ [English](README.en.md)

三个 [Claude Code](https://claude.com/claude-code) skill，覆盖学术论文工作的三段路：

> **读懂一篇**（`paper-analyzer`）→ **跑通一篇**（`paper-reproducer`）→ **看清一个方向／学科**（`direction-survey`）

不是「帮我把这篇论文总结一下」，而是把**一个论文知识库的完整运转流程**沉淀成可复用的指令集：固定产物形状、固定归档路径、固定完成线，让每一篇的产出都长一个样，可以互相比较、可以回溯、可以接力。

## 三个 skill

| skill | 一句话 | 触发语 | 主要产物 |
|-------|--------|--------|----------|
| [`paper-analyzer`](.claude/skills/paper-analyzer/) | 单篇论文**深度分析** | 「分析论文」「深度分析这篇 PDF」 | 结构化 md 报告 + **恰好两张** PNG（架构图 / 研究关系图）+ 图源 JSON |
| [`paper-reproducer`](.claude/skills/paper-reproducer/) | 论文**复现**闭环 | 「复现这篇论文」「跑通代码」「复现实验」 | `复现/README.md` 进度档 + `复现进度图.png` + 指标对齐结论 |
| [`direction-survey`](.claude/skills/direction-survey/) | **方向综述 / 学科论断** | 「出方向综述」「这个学科分成哪几个方向」 | 方向级 G1–G4 四图 + 演进综述；学科级 T1 学科地形图 + 逐块论断 |

三者共用同一套目录约定与版本口径，可以单独用，也可以串成一条流水线。

### paper-analyzer — 单篇论文深度分析 · v4.1.0

读一篇 PDF，走**九步深度分析**，产出一份结构化 Markdown 报告：

- **内容分层提取 + 页面体检**：PyMuPDF 分层抽取正文，稀疏页 / 扫描页回退到视觉补读，不只吃文本层。
- **核心逻辑与公式**：把论文的机制、损失、复杂度讲成人话，而不是复述摘要。
- **批判五段**（§4.1–4.5）：领域**失败模式必扫清单** → 不足点判定表（每篇 ≥8 条，带类别 / 严重度 / 置信度 / 是否可核验 / 改进建议）→ **致命一击**（针对论文最强主张的最强反驳）→ 可核验项就地登记 → Top-3 小结。
- **多库检索 5 篇分角色相关论文**：前驱 / 竞品 / 模块来源 / 后续 / 邻域，各司其职，不是"随便找五篇相关的"。
- **每篇报告恰好两张图**：§3.1 架构图（忠实数据流）与 §5.3 研究关系图（本文 vs 相关论文）。方向级的阶段 / 家族 / 机会叙事交给 `direction-survey`，不在单篇报告里重复。
- **默认产物 = 一篇 `md` 报告 + 两张 PNG**；`.docx`、`资源清单.md`、`复现/ 数据/ 资料/` 目录均为**按需**（显式要求时才做），默认链路省下的 token 用来把报告本身做深。

> 只说「找相关论文 / 查某篇的前驱后继竞品」时走**轻量检索模式**：只检索 + 出脉络，不产完整报告。

### paper-reproducer — 论文复现 · v2.1.3

对一篇论文走完「环境 → 数据 → 代码 → 冒烟 → 指标对齐」闭环：

- **完成线 = 在同口径下把论文的指标对上**（如 Table 3 的 VB-PESQ 3.58，带容差）。对不上就产出**差异分析**（三查），不硬凑、不改口。
- 全程用 `复现/README.md` 记录进度与卡点，脚本据此自动生成**复现进度图**：8 步三态 + 自动推导的「缺什么 / 下一步」。
- **缺口来源可叠加**：README 里未勾选的 `- [ ]`、状态块里 ⛔ 的步骤及其受阻原因、`资源清单.md` 中 `☐/⛔` 的资料行，都会被并进缺口列表——想补什么，写进这几处即可。
- 与 `paper-analyzer` 配套：消费分析报告的目标表 / 超参 / 官方数值，并把复现中发现的新链接、勘误、版本差异**回写** `资源清单.md`。

### direction-survey — 方向综述 / 学科论断 · v3.0.3

两种粒度，产物目标是「**读者不看任何单篇论文，也能看懂**」：

- **方向级**（缺省）：对一个细分研究方向出**以演进为主线**的综述——起源 → 骨干定型 → 分岔成几大技术家族 → 各家族沿革与卡点 → 生态里能比什么 / 不能比什么 → 前沿与缺口 → 下一步往哪走。配四张图：**G1 阶段演进带 / G2 技术家族泳道 / G3 机会象限（空白度 × 活跃度）/ G4 生态盘点矩阵**。论文只作为附着在阶段 / 家族上的证据，不逐篇点评。
- **学科级**：把一个学科切成细分方向，逐块给**成立度 / 成熟度 / 活跃度 / 空白度**四要素判断 + 边界一句话，并回答「哪块本不该单列、有没有该切而没切的一刀」。配 **T1 学科地形图**。证据薄时必须标「样本不足·推断」，不许硬判。

## 安装

skill 就是目录，把需要的整份拷进 Claude Code 的 skill 目录即可（**用户级**全项目可用，**项目级**只在单个仓库可用）：

```bash
git clone https://github.com/DomainW/paper.git
cd paper

# 方式一：用户级安装（推荐，任何目录都能触发）
mkdir -p ~/.claude/skills
cp -r .claude/skills/paper-analyzer   ~/.claude/skills/
cp -r .claude/skills/paper-reproducer ~/.claude/skills/
cp -r .claude/skills/direction-survey ~/.claude/skills/

# 方式二：项目级安装（只想在某个仓库用）
cp -r paper/.claude/skills/* <你的仓库>/.claude/skills/
```

安装后在 Claude Code 里直接说触发语即可，例如「分析论文」「复现这篇论文」「出方向综述」。也可以用 `/paper-analyzer` 之类的斜杠命令显式调用。

> **Windows 用户**：脚本输出中文，控制台需 `PYTHONIOENCODING=utf-8`，否则可能报编码错。

## 快速上手

### 分析一篇论文

1. 把 PDF 丢进 `论文库/<学科>/<方向>/未分析/`（不确定分类就丢 `论文库/_未分类/未分析/`）。
2. 对 Claude 说「**分析论文**」——skill 会递归扫描所有 `未分析/` 并列出候选。
3. 产出报告后自动整体归档到 `论文库/<学科>/<方向>/已分析/<发表年>/<论文名>/`：PDF → `原文/`，报告与两图 → `分析/`。
4. 需要 Word 版或复现资料，同一次请求里说明即可（`A+` 模式 / 步骤 8b）。

### 复现一篇论文

1. 对 Claude 说「**复现这篇论文**」（或在 `已分析/` 下点名某篇）。
2. skill 建 `复现/README.md` 骨架 → 环境 → 数据 → 代码 → 冒烟 → 指标对齐。
3. 每步更新后跑一次进度脚本，图与缺口清单自动刷新：

```bash
python .claude/skills/paper-reproducer/scripts/pr_status.py "<论文>/复现/README.md"
```

### 出方向综述

1. 确认该方向下已有若干篇**已分析**论文（它们是综述的证据）。
2. 对 Claude 说「**出方向综述**」（方向级）或「**这个学科分成哪几个方向**」（学科级）。
3. 产物落 `<方向>/方向综述/` 或 `<学科>/方向论断/`，含 md 报告与全套 PNG。

## 目录约定（论文库布局）

三个 skill 默认按下面的布局工作。**这是约定，不是硬编码路径**——你可以直接用，也可以改 skill 里的路径规范去适配自己的布局。

```
论文库/
└── <学科>/
    └── <研究方向>/
        ├── 已分析/
        │   └── <发表年>/              # 四位数字，无据者 年份不详
        │       └── <论文名>/
        │           ├── 原文/          # PDF + 提取文本
        │           ├── 分析/          # 报告 md + 两图 PNG + 图源 JSON
        │           ├── 复现/          # ◇按需：亲手跑的代码与笔记
        │           ├── 数据/          # ◇按需：数据集（下载脚本在 数据/下载脚本/）
        │           ├── 资料/          # ◇按需：官方代码 / 权重配置 / 评测脚本 / 补充
        │           └── 资源清单.md    # ◇按需：复现资料六类清单 + 收集状态
        └── 未分析/                    # 待分析（通常直接放 PDF）
```

三种状态：🟢 **已分析**（有 `分析/` 报告）｜🟡 **未分析**（只有原文）｜⚪ **未分类**（学科 / 方向未定，在 `论文库/_未分类/`）。

几条值得抄走的命名习惯：

- 论文文件夹名 = **英文原题（中文译题）**，标题多长就多长，不用简短别名。
- 标题里的半角 `:` 一律转全角 `：`（Windows 非法文件名字符）。
- 归档用**发表年**（会议年 / 期刊卷期年 / 学位论文答辩年），而不是下载或分析年份。

## 设计要点

如果你的 skill 也想这么写，这几处是最值得借鉴的：

1. **固定产物形状**：每篇报告恰好两张图、每份复现恰好一张进度图。「恰好」比「按需尽有」更难写，也更有用——产物可比、可批量巡检、可回归。
2. **完成线必须可判定**：复现的完成线是「指标对齐论文数值」，不写「跑通即可」；分析收尾跑 `_工具/table_check.py` 复查表格列数与转义，有问题**退出码 1**。可判定的完成线才能自动化。
3. **缺口自动推导**：进度图不靠人总结，直接从 README 的 `- [ ]`、状态块的 ⛔、清单里的 `☐` 推出来。
4. **证据纪律**：方向论断证据不足就标「样本不足·推断」；日期无据就标「不详」；复现对不上就写差异分析。**不臆造**是硬约束，写进了每个 skill 的正文。
5. **升级前先快照**：任何有版本语义的文件（skill 自身、报告模板）动工前整份快照留档，全部保留、不自动删除。踩过的坑见 [`docs/版本沿革.md`](docs/版本沿革.md)。

## 依赖与环境

skill 本体是 Markdown + Python 脚本。**扫描、检索、校验类脚本只依赖标准库**；只有 PDF 提取与出图需要装包：

| 用途 | 依赖 | 说明 |
|------|------|------|
| PDF 分层提取 | `PyMuPDF`（`import fitz`） | `paper-analyzer/scripts/pa_extract.py`；缺失时可回退视觉补读 |
| 出图 | `matplotlib` + `networkx` | `pa_fig.py` / `ds_fig.py` / `pr_status.py` / `pa_overview.py` |
| 转 Word | [`pandoc`](https://pandoc.org/) | 可选，仅按需出 `.docx` 时用 |
| 文献检索 | Semantic Scholar MCP | 可选，`pa_query.py` 另走 HTTP，不依赖 MCP |

```bash
pip install pymupdf matplotlib networkx
```

Python 3.9+（开发环境 3.13）。

## 仓库结构

```
paper/
├── .claude/skills/            三个 skill 本体（开源部分）
│   ├── paper-analyzer/        SKILL.md + scripts/ + references/ + templates/ + CHANGELOG.md
│   ├── paper-reproducer/
│   └── direction-survey/
├── _工具/                     仓库运维脚本（只读巡检：全库状态、复现缺口、表格自查等）
├── docs/                      仓库约定与版本沿革
├── CLAUDE.md                  本仓库的运转准则（Claude Code 每次会话自动读取）
├── 论文库/  ·  存档/          个人论文知识库与版本留档（本地，不入库）
└── README.md / README.en.md
```

每个 skill 目录下都有独立的 `CHANGELOG.md`，记录该 skill 的版本沿革与设计理由——那是最详细的一手资料。

## 仓库维护约定

本仓库同时是维护者个人的论文知识库，下列约定对它的持续运转有效，**细则见 [`docs/仓库约定.md`](docs/仓库约定.md)**：

- **版本留档约定**（第 5 节）—— 升级任何有版本语义的文件（skill 自身、报告模板）前，先整份快照到 `存档/`，全部保留、不自动删除。
- **版本口径约定**（第 6 节）—— 版本号与日期以 `SKILL.md` banner ／ 版本历史表 ／ `CHANGELOG.md` **三处一致**为准；日期以维护者改定的实际落地日为准，证据链与红线同节。
- **分类与命名规范**（第 4 节）—— 学科 / 方向的层级、论文文件夹命名、内部文件命名。
- **跨 skill 与仓库级事件沿革** —— 见 [`docs/版本沿革.md`](docs/版本沿革.md)。

给 Claude Code 的执行摘要（路径约定、归档口径、纪律红线）在根 [`CLAUDE.md`](CLAUDE.md)——它每次会话自动加载，改结构时请一并同步。
