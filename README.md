# 📚 paper — 学术论文知识库

个人学术资料库，**一切围绕两大核心目标**：

1. **论文分析**：读懂、批判、归档重点论文 → 产出结构化分析报告（Markdown + Word）
2. **论文复现**：针对重点论文跑通代码与实验 → 代码内嵌于论文文件夹，论文与复现一一对应

> 分析环节由 Claude Code 的 **`paper-analyzer`** skill 驱动（`.claude/skills/paper-analyzer/`）；方向级综述由 **`direction-survey`** skill 驱动（`.claude/skills/direction-survey/`）。本仓库的目录结构已与这些 skill 联动，详见下方「与 skill 的约定」。

## 两大核心目标如何使用

### 目标一：分析论文
1. 新论文 PDF 丢进 **`论文库/<学科>/<方向>/未分析/`**；不确定分类就丢 `论文库/_未分类/未分析/`。
2. 对 Claude 说「**分析论文**」→ 触发 `paper-analyzer` skill，它会**递归扫描所有 `未分析/`** 列出候选。
3. skill 产出报告后，会**自动把整篇移入同方向下的 `已分析/<论文名>/`**，`PDF→原文/`、`报告→分析/`，
   并建 `数据/ 资料/` 目录（`资料/` 内分 official-代码/ 权重配置/ 评测脚本/ 补充）+ 论文根 `资源清单.md`（复现资料六类分类清单：论文文档/官方代码/数据集/权重配置/评测脚本/环境依赖，逐项含 收集方法·许可·状态☐🔄✅⛔）。
   - 若论文原在 `_未分类`，归档前会请你确认它的学科/研究方向。

### 目标二：复现论文
- 复现环节由 **`paper-reproducer`** skill 驱动（`.claude/skills/paper-reproducer/`）：选论文 → 建 `复现/README.md` → 环境/数据/代码 → 冒烟 → 以**指标对齐论文数值**为完成线（对不上产出差异分析）。进度用 `复现/README.md` §0 状态块记录，并自动生成 `复现/复现进度图.png`（8 步走到哪 + 缺什么——含从论文根 `资源清单.md` 自动并入的 ☐/⛔ 未收齐资料行，见 skill 的「进度可视化」）。复现各步会照 `资源清单.md` 六类清单收集资料并**回写其状态与 §0 总览**。
- 代码放进该论文文件夹的 **`复现/`**，可再拆 `src/`、`notes/`、`结果/` 等。
- 复现目标、进度、结论建议以 `复现/README.md` 记录在代码旁（模板见该 skill 的 `templates/`）。
- 尚未配到论文的零散代码：先建 `未分析/` 下同名「待配论文」文件夹，待拿到该论文原文并入库后整体归位到 `已分析/`。**生命周期已完成示例**：原名 `SEMamba-训练代码(待配论文)` 的代码已配到学位论文《Research on State-Space-Based Speech Enhancement Algorithms…》，更名 `SEMamba-low-snr-normal-training-code` 归位于其 `已分析/<该论文>/资料/official-代码/` 下（2026-08-25）。

## 版本留档约定（改动前必做）

**升级/重写任何"有版本语义"的文件前，先把旧版整体快照到 `存档/`，再动手**：
- 范围：`.claude/skills/*`（SKILL.md + references + templates）、报告/清单模板，以及被取代的论文层文件（报告草稿、`资源清单.md` 旧版等）。
- **⚠️ 升级一个 skill 时，除论文层产物外必须同时快照该 skill 自身**（2026-09-18 立规；反面案例：paper-analyzer v4.0 只快照了论文层，导致自身版本基线缺失）。
- 存放：`存档/skills-前版本/`（按 skill 分子目录）与 `存档/论文层快照/`。
- 命名：`<原名>-v<版本>-<YYYY-MM-DD>.<ext>`；**全部保留、不自动删除**。
- Markdown 快照头部加一行 `<!-- 快照：来自 <原路径>；<日期> 归档；因 <原因>；被 <新版本> 取代 -->`。
- 细则与索引见 `存档/README.md`。

## 版本口径约定（单一事实源 · 2026-09-18 立规）

每个 skill 的版本号/日期以**三处一致**为准：`SKILL.md` 顶部 banner ／ `SKILL.md` 底部「版本历史」表（**由新到旧**）／ `CHANGELOG.md`「当前版本」。
- **日期** = 该版本实际落地日，**以维护者在各 skill 版本历史表内改定的时间为准**；证据链 **维护者改定 > 存档快照 > `CHANGELOG` > banner > 版本历史表**；**文件系统 mtime 不作落地日依据**（本地 skill 文件 mtime 多为 2026-09-05/09-06 入库时刻）、**快照文件名/索引里的日期 = 归档日**（不顶替落地日）；无据者标「不详」，**不臆造**。
- **2026-09-18 库内版本时间线统一（现行口径的首批，非「一次性例外」）**：为使全库时间分布可读，该日把版本时间线按维护者改定铺开——**首批** `paper-analyzer：v1.0 2024-06 · v2.0 2026-07-05 · v3.0 2026-08-05 · v3.1 2026-08-11 · v3.2 2026-08-25 · v4.0 2026-09-06 · v4.0.1 2026-09-18 · v4.0.2 2026-09-18`；**第二批（同日）** `direction-survey：v1.0 08-05 · v2.0 08-26 · v2.1 09-06 · v2.1.1 09-18 · v3.0 09-18 · v3.0.1 09-18`、`paper-reproducer：v1.0 不详（档于 09-05）· v2.0 08-05 · v2.1 08-26 · v2.1.1 09-18`。各报告「生成日期」= 产出它的 skill 版本落地日（资源清单同其报告，馆藏与存档索引随版本）；论文出版年/答辩日期/第三方 upstream 版本号一律不动。**此后新版本照此办理**（口径已是常规）。
- **2026-09-19 增量（照常规口径办理）**：`direction-survey v3.0.2`（关联 skill 戳对齐·无功能变更）· `paper-reproducer v2.1.2`（缺口解析修复）· `paper-analyzer v4.0.3`（表格竖线转义纪律 + 完成线自查，同日修订补「代码段内竖线 / 裸反斜杠」两处细节）——均 **2026-09-19** 落地，三处已一致；三个 skill 动工前均整份快照入 `存档/skills-前版本/`。详见各 skill `CHANGELOG.md` 与 `存档/README.md` 索引/事件段。

## 分类与命名规范（整体结构规范）

### 1. 分类层级
- **学科（一级）/ 方向（二级）**用中文，可附英文缩写，如 `语音与音频信号处理`、`目标说话人提取与语音分离(TSE)`。
- 每个方向下固定含 **`已分析/` 与 `未分析/`** 两个状态目录；新学科/方向按需 `mkdir`。
- 拿不准归属的新论文先丢 `_未分类/未分析/`。

### 2. 论文文件夹命名 —— 统一使用「英文原题（中文译题）」✅
> 每篇论文（在 `已分析/<方向>/` 下）占一个文件夹，**文件夹名 = 论文原题完整英文名称，后附中文完整译题**，格式 `英文原题（中文译题）`，不使用简短别名。

规则细节：
- 英文原题与中文译题均含副标题；外文专有名词（模型名 / 体系名 / 缩写）保留原文不意译，如 `SpeakerBeam-SS`、`Conv-TasNet`、`CrSb`。
- **英文标题里的冒号一律改用全角 `：`**（半角 `:` 是 Windows 非法文件名符号）；中文括号、顿号等标点同样用全角。
- 标题多长就用多长（NTFS 单级名上限 255 字符）。
- 例：英文原题 `SpeakerBeam-SS: Real-time Target Speaker Extraction with Lightweight Conv-TasNet and State Space Modeling` + 中文译题 `SpeakerBeam-SS：基于轻量级Conv-TasNet与状态空间建模的实时目标说话人提取`
  → 文件夹名 `SpeakerBeam-SS：Real-time Target Speaker Extraction with Lightweight Conv-TasNet and State Space Modeling（SpeakerBeam-SS：基于轻量级Conv-TasNet与状态空间建模的实时目标说话人提取）`
- **例外**：非单篇论文的辅助夹可用描述性命名，并尽量在文件夹名中标明用途（历史例 `SEMamba-训练代码(待配论文)`，现已更名归位，不再有实例）。

### 3. 内部文件命名
- `原文/` 保留原始下载文件名（arXiv 编号等），不因文件夹改名而改动。
- `分析/` 报告命名风格：`<论文名>-分析报告.md` / `.docx`。
- 中文译名 ↔ 英文原题 / 原始文件 的对照表，维护在 `论文库/README.md` 的**馆藏清单**中（新建论文文件夹后同步登记）。
